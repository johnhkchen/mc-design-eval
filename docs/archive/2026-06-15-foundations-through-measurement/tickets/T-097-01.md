## Context (self-contained)

Epic **E-26** / Story S-097. The artifact contract half-supports fixtures already: placements carry an
optional `state` (`src/artifact.mjs`, `schema/design-artifact.schema.json`) and the render path applies
block + orientation (`render/src/world.mjs` → `setBlock(world, pos, block, state)`, illegal states
recorded in `unmapped`). But **no generator has ever emitted a non-cube block** (repo-wide grep: zero
trapdoor/fence usage), and the analysis layers assume full cubes: `src/view/occupancy.mjs` is
solid-or-empty, so the E-25 six-direction closure check would read a fence-infilled window as a **hole**.
Unproven path + wrong semantics = the kit can't ship fixtures yet.

## Acceptance Criteria

- [ ] A **fixture test-card**: one artifact placing each needed fixture type (trapdoor, fence, stairs,
      slab) at each orientation/state the kit grammar will use; rendered; every placement verified
      correct (right block, right facing) — `unmapped` must be empty. The card + render saved as the
      regression reference.
- [ ] The **live AJV gate accepts** every state the test-card uses (extend the schema only if a needed
      state shape is rejected — record what changed).
- [ ] **Occupancy semantics defined + implemented** (pure, unit-tested): fixture cells are a third class
      (not solid, not empty) — `occupancy` exposes them distinctly so downstream ops can choose.
- [ ] **Closure/integrity semantics** (with E-25 S-091 in mind): a **dressed opening** (fence/trapdoor in
      an `openings` aperture) passes the six-direction closure check as *dressed*, not as a hole; a
      fixture floating in a wall field is still flaggable as stray. Unit-tested both ways.
- [ ] **Structural read**: `openings` detection still finds a dressed opening (its identity survives
      dressing — needed by the grammar and interior checks). Unit-tested.
- [ ] No subject-specific constants; `npm test` green.
