## Context (self-contained)

Epic **E-38** / Story **S-160**. This is **"the finding"** T-160-01 named: for sparse/ragged GLB shells,
the wall envelope can't be recovered from the occupancy alone — it must be built from the recognized
program's **absolute clean rectangle, registered to the build frame**.

**The evidence (T-160-01 review):** `construct_walls` (Option B) derives the footprint from the
occupancy and morphologically closes it. That works when the shell is dense (gatehouse, 32%-filled,
square → climbed +20, clean solid walls). It **fails on sparse shells**: the barn shell is only **20–22%
column-filled** and ragged; **morphological close provably cannot bridge straight-run absent columns**
(asserted as a limit in test WG1 — dilate/erode shadow a flat-boundary gap). So the barn stays a
**"colonnade of posts"** under its roof (+1, see-through) no matter how the occupancy is closed. Closing
those straight runs needs a *clean rectangle*, and the only clean rectangle available is the program's
`masses[].rect`.

**The crux (design.md):** the program rect is in a **0-based local frame** (barn: `{x0:0,z0:0,w:48,d:24}`)
with **no registration** to the build's **negative-coord** frame and no shared anchor. T-160-01 chose
Option B precisely to avoid gambling the climb on unscoped registration. This ticket scopes that
registration as its own problem — which is the honest, evidence-driven way to take it on.

Reuse: `src/view/wall-generate.mjs` + `wall-generate.test.mjs` (WG1–WG8, the Option-B brush this
extends), `src/view/occupancy.mjs` (eave-band extraction), `experiments/eval-alignment/autonomy-loop.mjs`
(the loop), `experiments/eval-alignment/defect-eval.mjs` (the trusted, untouched measure). Recognized
program: `benchmarks/sculpture/recognition/<subject>.program.json`.

## Falsifiable claim (anti-hedge — lead with how it fails)

The program rect can be registered to the build frame from a **robust shared feature — the occupancy's
eave-band extent** (the outermost posts exist even when interior columns are missing) — by fitting the
clean `w×d` rectangle to that extent over a **small ladder of axis assignments judged by occupancy
coverage** (no per-subject constants). Building the envelope from that **registered clean rectangle** will
**close the barn's straight-run gaps** (the barn climbs where Option B left it a colonnade) **without
misplacing the walls** (no regression on the dense shells gatehouse/cottage, which Option B already
solves).

**It fails if:** (a) the eave-band extent is **outlier-polluted** (a stray post overshoots the bbox) and
the fitted rectangle lands off the true wall line → walls misplace and the build **regresses** (then a
robust/percentile extent, not raw min/max, is the sub-fix — flag it, cf. the glb-end-fit anchor-window
lesson); (b) the program rect **doesn't match** the occupancy extent up to axis swap (scale or shape
mismatch) → registration is **ambiguous**, and that ambiguity *is* the finding (the program frame and the
build frame are not relatable by rigid transform — report it, don't force a fit); (c) registration
succeeds and the barn **still doesn't climb** → then the colonnade was not the barn's cap and the gate is
elsewhere (roof-prism / material) — report where. **Verify with a render beside the concept**; the eval
score alone can't tell a closed wall from a colonnade at coarse resolution.

## Acceptance Criteria

- [ ] A **registration function**: given a program `masses[].rect` and the build occupancy, return the
      rigid placement (translation + axis assignment, scale only if the data demands it) of the clean
      rectangle in the **build frame**, chosen from a **ladder of candidates ranked by occupancy
      coverage** — not tuned constants. Pure + unit-tested; include a test that the **straight-run gap
      WG1 leaves open is now closed** by the registered path (the companion to WG1's documented limit).
- [ ] `construct_walls` gains a **registered-rectangle envelope path** (build floor→eave on the
      registered rect's perimeter), used when it out-covers the close-derived footprint — so dense shells
      keep Option B and sparse shells get the clean rectangle, decided by coverage, **not** a per-building
      density threshold or subject key.
- [ ] Wired into `autonomy-loop.mjs` as part of the wall tool (still minimal — finer geometry, not a new
      tool the agent must choose). Re-run the volume batch (cottage, barn, gatehouse); **barn is the
      witness case**.
- [ ] **Recorded honestly with renders beside concept:** do the barn's straight-run gaps close (solid
      wall, not colonnade)? Do gatehouse/cottage hold (no regression)? If registration is ambiguous for a
      subject, say so and localize whether the frames are relatable at all.
- [ ] `npm test` green; no per-building constants (honor the recognize.mjs self-grep discipline); the eval
      (`defect-eval.mjs`) untouched.
