## Context

Epic E-14 / story S-040 — the **concept end**. Make Nano-Banana generate the concept against the **real
block values** so it stops over-promising (closes `[[concept-image-not-color-value-preview]]`: the
concept blocks hue, not value). Additive — clone the frozen prompt, never edit it, so E-13 `.v1` runs
stay reproducible.

Do: add a `SculptureConceptPrompt` **`.v2` variant** in `baml_src/conceptart.baml` that consumes the
value-true palette (T-039-01) and **attaches a rendered swatch grid of the actual blocks** as a
multimodal input (reuse E-10 `renderGridSwatch` / `image-grid.mjs`; attach via `src/nano-banana.mjs`,
the same path `baml-concept.mts` uses). Tell the model: match these *real* block swatches' value, not an
imagined hue. Run the `.v2` concept on a few E-13 sculptural subjects (the moai + one organic) and **A/B
vs the `.v1` concept** — does `.v2` preview the true (often darker) value, narrowing the surprise the
render later exposes?

## Acceptance Criteria

- [ ] A `SculptureConceptPrompt` **`.v2`** exists alongside the untouched `.v1` (frozen prompt
      unchanged — diff shows an addition, not an edit); `baml:gen` regenerates cleanly.
- [ ] The real-block **swatch grid** (from T-039-01's palette card) is attached as a multimodal input to
      the concept generation, and the prompt instructs value-matching to those swatches.
- [ ] An **A/B** is recorded: `.v2` vs `.v1` concept for ≥2 subjects (moai + one organic), with a note
      on which previews value more honestly (and any segmentation/quality cost).
- [ ] Artifacts saved (both concepts + the swatch grid); `npm test` green.
