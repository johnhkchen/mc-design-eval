# T-019-01 — Structure: files, interfaces, boundaries

The blueprint. No code bodies — shapes, signatures, ordering.

## Files

### CREATE `src/color/block-table.mjs`  (the module — logic + I/O, importable)

Top doc comment: what/why, the S-023 dedupe note for `srgbToLab`, the 1.20.1→1.20.2 resolution
note, devDependency boundary.

Pure helpers (exported, unit-tested):
- `srgbToLab([r,g,b]) -> [L,a,b]` — forward conversion per the research-doc math. Internally:
  `srgbChannelToLinear(c0_255)`, `linearRgbToXyz()`, `xyzToLab()`. Only `srgbToLab` is exported;
  the rest may be module-local. (Duplicated from the future `cielab.mjs`; see header.)
- `pickFace(model) -> { kind, texture }` — given a `blocksModels[name]` entry, return the chosen
  face name and the resolved PNG stem (strip `minecraft:`/`block/`). Encodes the D4 face rules.
  Returns `null` when no usable opaque face texture (caller records exclusion).
- `meanOpaqueRgb(png, alphaThreshold=128) -> [r,g,b] | null` — png is `{width,height,data}`
  (RGBA8, pngjs shape). Uses **first frame** rows `0..width-1` when `height>width &&
  height%width===0`. Returns `null` if no pixel meets the threshold (after a >0 fallback).
- `isFullCubeParent(parent) -> boolean` — true iff stripped parent starts with `block/cube`.
- `EXCLUDE_BLOCKS: ReadonlySet<string>` — the D3 denylist.
- `classifyBlock(name, model) -> { include: boolean, reason?: string }` — single source of the
  D3 selection logic (real-block-ness is checked by the builder via the textures name-set,
  passed in, since the model alone can't tell).

I/O + orchestration (exported):
- `resolveAssets(version="1.20.1") -> { directory, version, models, textureNames }` — default-
  import `minecraft-assets`, call it, read `blocks_models.json` + `blocks_textures.json` from
  `.directory`. The ONLY place the package is touched.
- `buildBlockTable({version="1.20.1"} = {}) -> { version, requestedVersion, generatedFrom,
   blocks: Entry[], excluded: {block,reason}[] }` — orchestrates: resolve → iterate model keys ∩
   textureNames → classify → for included, pickFace → read+decode PNG (`PNG.sync.read`) →
   meanOpaqueRgb → srgbToLab → Entry. Deterministic: results sorted by block name. Records every
   dropped block in `excluded` with its reason.
- `loadBlockTable(path?) -> table` — read + JSON.parse the committed
  `src/color/block-lab-table.json` (default path resolved relative to this module). The accessor
  S-020/S-021 use; no asset deps on this path.

`Entry` shape: `{ block: string, texture: string, rgb: [int,int,int], lab: [number,number,number] }`.

No top-level side effects; `pngjs` is imported lazily inside `buildBlockTable`/the decode helper
so that `loadBlockTable` and the pure helpers are importable without the dev dep present at
runtime (keeps the runtime-clean boundary real, not just nominal).

### CREATE `scripts/build-block-table.mjs`  (the CLI)

Thin: parse optional `--version` / `--out`, call `buildBlockTable`, write pretty JSON to
`src/color/block-lab-table.json`, print a one-line summary (`N blocks, M excluded, version=…`).
Mirrors `scripts/validate-artifact.mjs` style (shebang-free, `node ...` invocation).

### CREATE `src/color/block-lab-table.json`  (the committed output)

Generated by the CLI in the Implement phase; committed. Shape per D6.

### CREATE `src/color/block-table.test.mjs`  (the suite)

`buildBlockTable` (no asset deps in the test path; tests validate the committed artifact).

## Module boundary / dependency direction

```
scripts/build-block-table.mjs ─uses→ src/color/block-table.mjs ─reads→ minecraft-assets (devDep, build-time)
                                                              └─decodes→ pngjs (devDep, build-time)
src/color/block-table.mjs  ──writes/reads→  src/color/block-lab-table.json   (committed data)
                                                   ▲
S-020 cielab engine / S-021 extractor ─────────────┘ (runtime: import loadBlockTable / the JSON; NO asset deps)
```

Hard rule: nothing on the **runtime** path (`loadBlockTable`, the JSON, S-020/S-021) may pull
`minecraft-assets` or `pngjs`. Enforced by lazy-importing `pngjs` only inside the build helpers.

## Ordering of changes (matches plan.md)

2. `src/color/block-table.mjs` — pure helpers first (`srgbToLab`, `meanOpaqueRgb`, classify,

3. `scripts/build-block-table.mjs`; run it → produce `block-lab-table.json`.
4. `src/color/block-table.test.mjs`.
5. `npm test` green; commit.

## Interfaces other tickets rely on (stability contract)

- `loadBlockTable()` and the `block-lab-table.json` schema (`{version, blocks:[{block,rgb,lab}],
  excluded}`) are the **public contract** for S-020/S-021. Keep `block`, `rgb`, `lab` field names
  stable; additive fields (`texture`, provenance) are fine.
- `srgbToLab` is intentionally **internal/transitional** — S-023 may delete it in favor of the
  engine's. Downstream code should depend on `cielab.mjs` for conversion, not on this module.
