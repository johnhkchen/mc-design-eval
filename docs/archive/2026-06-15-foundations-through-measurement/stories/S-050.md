## Background (self-contained)

Epic **E-16**, Arm B — the founding image→3D question. The project's working build path is text→JSON: the
model emits voxel placements, which keeps palette + parts but loses *form/line* (a koi's S-curve flattens,
a heart's aortic arch never loops — E-13). A standing alternative (the Falcraft approach) is to skip
text→JSON geometry entirely and **voxelize a 3-D mesh directly**. We now have real meshes
(`benchmarks/sculpture/glb/{koi,heart}.glb`, ~95–106K tris) to try it.

This story builds the geometry half: **mesh → occupancy voxel grid** at a target scale. For each cell in a
grid sized to the mesh's bounds at `--scale` longest-edge voxels, decide occupied/empty by a deterministic
test (point-in-mesh via ray-cast parity / winding, or triangle-vs-cell intersection for a watertight
shell). Pure geometry — no GL, no color yet — so it's fully unit-testable on a synthetic mesh.

## Goal

`voxelizeGlb(glb, { scale }) → occupancy` — a deterministic occupancy grid (the set of occupied integer
cells + bounds) from a GLB mesh, sized so the longest edge is ~`scale` voxels (reuse the `vConcept`
scale convention, `DEFAULT_SCALE` in `src/sculpture.mjs`). Pure, GL-free, unit-tested on a synthetic cube
(known occupancy) so the suite stays offline; a real koi occupancy count sanity-checked.

## Builds on

- The GLB mesh load from S-048 (vertices + triangles) — share the parser, don't duplicate it.
- The `vConcept` scale convention (`src/sculpture.mjs` `SCALE_MIN/MAX/DEFAULT_SCALE`,
  `sculptureScaleCaps`) so a voxelized build is comparable to the text→JSON build at the same scale.

## Run-the-test ticket

- `T-050-01` — implement `voxelizeGlb` (mesh → occupancy at a target scale); unit-test occupancy on a
  synthetic cube; sanity-check real koi/heart occupancy counts vs their scale.
