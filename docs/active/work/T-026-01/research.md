# T-026-01 Research — review-bookend (diagnostic critic)

Epic **E-11** / story **S-026**, bookend 2. Map the existing code the critic must consume,
the BAML categorical-judge pattern it must follow, and the boundaries it must respect.
Descriptive only — options and decisions live in `design.md`.

## What the ticket asks for

A **critic** that takes a build state, renders it (E-02 head-on), and emits a **structured
diagnosis**: `{ defect, where, route }[]` where `defect ∈ {flat, ringing,
under-detailed-focal, proportion}` and `route` names the stage that should re-run. It
**routes, it does not rebuild** — the P14 cure. It must be a **stage-agnostic consumer** of
the build state (no coupling to specific passes), tested against a **fixture** build state
with a known defect (a flat untextured wall), with the model call stubbable.

## The build state it consumes (`src/sculptor/build-state.mjs`, T-024-01)

The dependency (T-024-01) is the framework spine. The relevant surface:

- `BuildState` = `{ width, height, cells: Map<"x,y", Cell>, locked: Set<field>, lockLog }`,
  frozen. `Cell` = `{ occupied: boolean, material: string|null, relief: number }`. Sparse:
  an absent key reads as `defaultCell()` = `{occupied:false, material:null, relief:0}`.
- `FIELDS = ["occupied","material","relief"]` — the canonical lockable fields.
- Read helpers: `getCell(state,x,y)`, `occupiedCells(state)` (sorted `(y,x)`, returns
  `{x,y,cell}[]` for occupied cells only), `isLocked(state,field)`.
- `lockLog: {stage, fields}[]` — the ordered accept record naming **which stage wrote which
  field**. This is the only place stage names already appear in a state.
- Mutation is via `draftState`/`Draft.set`/`lockFields` — the critic does **not** mutate; it
  is a pure reader of the state plus its render.

Key fact for routing: the build state already tells us, per cell, whether `material` is set
(`null` = un-textured) and whether `relief` is non-zero (flat = 0). That is enough to
disambiguate the one ambiguous route (`flat → material` vs `flat → relief`) *from the state
itself*, without coupling to any pass.

## How a state becomes an image (`src/sculptor/compile.mjs` + render core)

- `toDesignArtifact(state, opts) → DesignArtifact` (pure): one `voxel` placement per occupied
  cell at `[x, y, relief]`, `block = cell.material ?? defaultBlock`, manifest derived. Throws
  if no occupied cells. This is the **compile-down** the critic reuses to get a renderable
  artifact from a build state.
- `render/src/render-tool.mjs` `renderArtifact(artifact, {outPath, view}) → RenderReport`
  (`{path, bytes, placed, unmapped, bounds}`). Headless GL/prismarine. Heavy — lazy-imported
  everywhere it is used (`render-tool.mjs`, `iterative-multimodal.mjs`).
- `src/render-tool.mjs` (the SDK-tool wrapper) shows the canonical lazy-import boundary:
  `const { renderArtifact } = await import("../render/src/render-tool.mjs")` only inside the
  live handler, so pure tests never load GL. The critic must follow this.

E-02 head-on is the default view. Multi-view (E-12 turntable) is explicitly an *opportunistic
upgrade*, out of scope here.

## The categorical-judge BAML pattern it must mirror

The existing judge is the template (`benchmarks/temple-facade/`):

- **`baml_src/judge.baml`** — declares `enum Category { Weak Competent Strong Exceptional }`,
  `class FacadeScore { proportion Category … notes string }`, and
  `function JudgeFacade(brief: string, render: image) -> FacadeScore`. The prompt embeds
  `{{ render }}`, `{{ brief }}`, per-dimension anchors, and `{{ ctx.output_format }}` — the
  enum-constrained output spec BAML injects. Output is small, so no prose-wrap problems.
- **`baml_client/`** — generated TS client (`b.request.JudgeFacade`, `b.parse.JudgeFacade`).
  Regenerated by `npm run baml:gen` (`baml-cli generate --from baml_src`); CLI **0.222.0 is
  installed**, generator targets TS, `output_dir "../"` → `baml_client/`.
- **`benchmarks/temple-facade/baml-judge.mts`** — the live, metered tsx stage. Reads
  `{imagePath, brief, samples}` on stdin; per sample: `b.request.JudgeFacade(brief, Image)`
  renders the prompt, **pipes it through `requestTextWithImage` (claude -p, subscription)**,
  brace-slices the reply, `b.parse.JudgeFacade(cleaned)` → typed score; median-aggregates.
- **`benchmarks/temple-facade/judge.mjs`** — `judgeRender()` spawns `npx tsx baml-judge.mts`
  and JSON-parses stdout. This is the `.mjs ↔ .mts` bridge: the BAML client is TS, so the
  live call runs in a tsx subprocess; pure `.mjs` code spawns it. The critic's live seam must
  use the same spawn-tsx bridge.

The pattern, distilled: **enum-constrained categorical output + image-in + SAP/brace-slice
parse, model call piped through `requestTextWithImage`.** The defect vocabulary is an enum
exactly as `Category` is.

## The model seam (`src/sdk-binding.mjs`)

- `requestTextWithImage({prompt, images, model, …}) → {text, raw}` — image(s) in, plain text
  out, **no schema** ("the basis for the LLM-as-judge"). This is what baml-judge pipes BAML's
  rendered prompt through. The critic's diagnose stage uses the same function.
- `requestDesignArtifactWithImage` (schema-forced) is **not** what we want — the critic emits
  a diagnosis, not an artifact (and emitting an artifact would be the P14 re-emit anti-pattern
  the ticket forbids).

## The P14 lesson (`docs/knowledge/design-learnings.md`)

P14 = the **2nd-pass double-edge**: a blanket "improve" revision that re-emits the whole
artifact can *detach masses* and regress a strong round-0 (run 020: recessed portal+rose →
flat gold slab). The structural cure already lives in the spine: **locks make improve
additive**. The critic is the *diagnostic* half of that cure — it must name a defect and
**route it to the responsible stage**, never hand back a rebuilt artifact. "Routes, never
re-emits" (AC#2) is P14 encoded in the critic's output type.

## Codebase conventions the critic must follow

- **Layering** (every live module: `iterative-multimodal.mjs`, `render-tool.mjs`): pure
  helpers tested by `npm test`; the one live/metered/GL function lazy-imports its heavy deps
  and is **not** unit-tested. Pure-vs-live split is explicit in file headers.
- **Test wiring:** `npm run test:unit` = `node --test "src/**/*.test.mjs"` — a
  `src/sculptor/review.test.mjs` is auto-discovered. Full `npm test` also runs the AJV
  self-tests. Baseline is **230/230 green** (T-024-01).
- **Sculptor boundaries** (`src/sculptor/README.md`): the spine modules are pure (no SDK, no
  render, no schema). The README explicitly anticipates "the review critic plug[s] into it as
  [a] downstream ticket" — so the critic is the sanctioned place to cross that boundary, via
  lazy imports, exactly as the trial archetypes do.
- **Injectable seams:** existing live functions accept their heavy collaborators implicitly;
  for a *unit-testable* critic the render+diagnose calls should be injectable so the routing
  logic can be exercised end-to-end with stubs (the ticket: "model call may be stubbed").

## Constraints / assumptions surfaced

- `where` from an image judge is necessarily a **free-text region** ("the central bay"), not
  cell coordinates — the model judges what it sees. Routing therefore keys on `defect` (+ the
  build state for `flat`), never on parsing `where`.
- A clean fixture must yield **no defects** — this is a property of the model's judgment;
  under stubbing it is the "diagnose returns `[]` → diagnosis is `[]`" path.
- BAML render needs an `ANTHROPIC_API_KEY` present *to render the prompt template only* (never
  sent); baml-judge sets a dummy key then deletes it before the subscription call. Any new
  tsx stage must replicate that dance.
- Regenerating `baml_client` touches generated files broadly but is deterministic via
  `npm run baml:gen`; adding one BAML function is additive.
