# T-165-01 — Structure

The file-level blueprint. Not code — the shape and ordering of the change.

## Files MODIFIED

### `schema/building-program.schema.json`
- Add an **optional** `style` property to the top-level `properties`:
  `"style": { "description": "Style slug the program was recognized under (today == pack id). Stamped at
  the recognition seam; the eval's Layer-A suite is selected by it.", "type": "string", "pattern":
  "^[a-z][a-z0-9-]*$" }`.
- **Not** added to `required` → committed records without it still validate.
- `additionalProperties: false` stays; `style` is now a *known* property so a stamped program validates.

### `src/recognition/prompt.mjs`
- `baseRecognitionSchema(schema)` — after the `facade` delete, also `delete s.properties?.style;` so the
  model-facing `schema_json` is byte-identical to the pinned FX-R1 prompts (the model never authors style).
- (No change to `recognitionRenderArgs` / `parseProgramReply` signatures.)

### `benchmarks/sculpture/recognize.mjs`
- After `parseProgramReply(...)` yields the validated program (both the live path `:152`-area and the
  `--repro` committed path `:228`-area), **stamp the declared style**: `program.style = pack.style` before
  the program is written / used. One small helper or inline; the stamp is idempotent (re-stamping the same
  value). This is "recognition declares the style" — honestly, from the conditioning pack.

### `baml_src/department.baml`
- `DiagnoseBuild` gains one input `style_profile: string`, placed after `palette_block`.
- The prompt body gains, after the palette block, a section:
  `THE STYLE'S CONSTRUCTION GRAMMAR (what this style's roof / walls / openings should read as): {{
  style_profile }}`. No gate vocabulary, no proportion, no actions/rounds. Style-grammar only.

### `src/baml/bridge.mts`
- `FNS.DiagnoseBuild.request` passes the new positional arg:
  `b.request.DiagnoseBuild(a.style, a.image_list, a.program_block, a.palette_block, a.style_profile,
  a.departments, a.max_items, toImage(img.concept), ...)`. Order matches the BAML signature.
- Then `npm run baml:gen` regenerates `baml_client` (pretest also runs it).

### `src/workshop/diagnose.mjs`
- New pure export `styleProfileBlock({ pack })` → the per-style roof/wall/opening grammar block, derived
  from `pack.idioms` + `pack.palette` (+ `pack.proportions.pitchClasses` for the roof line). No subject
  names; deterministic; pure.
- `diagnoseRenderArgs({ program, pack, azimuths, maxItems })`:
  - `style: program?.style ?? pack.style` (the **declared** style, honest legacy fallback).
  - add `style_profile: styleProfileBlock({ pack })` to the returned object (positioned between
    `palette_block` and `departments` to mirror the BAML order).

### `src/workshop/diagnose.test.mjs`
- **DG5** (new): `styleProfileBlock` differs between rustic and saltcrag on concrete grammar tokens
  (roof material spruce vs dark-oak; wall grammar timber-frame vs limewash; saltcrag ridge tiles) — the
  AC2 within-family gradient, pure + offline. Also assert it carries **no subject string** and is
  deterministic.
- **DG6** (new): `diagnoseRenderArgs` keys `style` on `program.style` when present, falls back to
  `pack.style` when absent (the declared-style selection + honest fallback).
- Adjust DG1–DG4 only if they pin the exact returned key set / `style` source (additive `style_profile`
  key; `style` now sourced from program — update the fixtures' program to either carry or omit `style` as
  the assertion intends).

## Module boundaries (unchanged)

- **Pure core**: `diagnose.mjs` (serializer + `styleProfileBlock`) — no IO/GL/Date/random.
- **Seam (IO)**: `recognize.mjs` stamps style + loads packs; `workshop.mjs` `--split` passes
  `{program, pack}` (already does). The pack-by-style *lookup* (registry) stays at the seam.
- **Contract**: `building-program.schema.json` (now with optional `style`); `department.baml`
  `DiagnoseBuild` (now with `style_profile`). The frozen `Critique`/`Department` classes are untouched.

## Ordering (matters)

1. Schema `style` (optional) + `baseRecognitionSchema` strip + prompt.test guard — keeps recognition pinned.
2. `recognize.mjs` stamp — recognition now declares style.
3. `diagnose.mjs` `styleProfileBlock` + `diagnoseRenderArgs` (style from program, add `style_profile`) +
   DG5/DG6 — pure, testable without the bridge.
4. `department.baml` + `bridge.mts` + `baml:gen` — wire the new input.
5. Regenerate diagnose `inputs.json` + `prompt.golden.txt`; FX-DB1 string assert — pin the golden.
6. Full `npm test` green; frozen instrument + FX-R1 untouched.
