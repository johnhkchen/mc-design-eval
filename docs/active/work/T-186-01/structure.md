# T-186-01 — STRUCTURE (file-level change map)

The blueprint: which files change, the new framing strings, the regeneration order, and what stays
frozen. No new modules; no schema change; no scoring-core edit.

## Files MODIFIED

### 1. `baml_src/department.baml` — the `DiagnoseBuild` prompt (the standard re-frame)
The load-bearing edit. Reword the prompt body so the **concept image is the standard** and the
style/material blocks are a **naming vocabulary**:
- Replace *"Judge it against THIS STYLE'S grammar above — the SAME build is correct under one style and
  wrong under another."* with a **picture-anchored** instruction: the expected roof/walls/openings are
  **what the CONCEPT IMAGE shows**; the blocks below name materials/idioms only.
- Add the **inverting sentence**: a build that matches its concept image is correct even if its
  materials differ from the vocabulary; a build that does not match its concept image is wrong even if
  every material is from it.
- Re-key `replace`/`add` semantics to **build-render-vs-concept-image** (replace ⇒ built unlike the
  picture; add ⇒ an element the picture shows is absent). Keep the typed-`kind` schema line.
- Headers `{{ palette_block }}` / `{{ style_profile }}` keep their slots; their *content* re-frames in
  diagnose.mjs (below).
- **Do NOT** touch `RouteCritique`, the enums, or the `Critique`/`CritiqueItem` classes.

### 2. `src/workshop/diagnose.mjs` — re-label the two pack blocks as vocabulary
- `styleProfileBlock({pack})`: change ONLY the header line from
  *"THE STYLE'S CONSTRUCTION GRAMMAR (what a `${style}` build's roof / walls / openings should read as
  — element construction, not size):"* to a vocabulary frame, e.g.
  *"NAMING VOCABULARY — the `${style}` pack's materials & idioms, available to DESCRIBE the build and
  its concept (NOT the standard; the CONCEPT IMAGE is the standard):"*. Body (ROOF/WALLS/OPENINGS
  role→block + idiom lists) unchanged.
- `paletteBlock` lives in `critique.mjs` (imported). Its header is rendered in the prompt template
  preface (*"THE STYLE'S MATERIAL VOCABULARY (what the concept's blocks should be):"*) — that preface
  string is in `department.baml`, so re-frame it THERE (step 1), not in critique.mjs (shared by the
  fused path; do not perturb it).
- Update the doc-comment on `styleProfileBlock`/`diagnoseRenderArgs` to state the new contract: the
  pack supplies vocabulary; the concept image is the expected.

### 3. `src/workshop/diagnose.test.mjs` — update intent + add the picture-anchoring pin
- DG5/DG7 body assertions stay (the role/idiom lists are unchanged). Update their **comments** (no
  longer "the EXPECTED grammar"; now "the naming vocabulary that still differs per pack").
- Add **DG8**: assert `styleProfileBlock` header no longer claims the pack is what the build "should
  read as" (the inverted framing) — `assert.doesNotMatch(r, /should read as/)` and
  `assert.match(r, /NOT the standard|naming vocabulary/i)`. This is the unit tripwire for the re-frame.

### 4. `src/baml/fixtures/diagnose/inputs.json` — regenerate the `style_profile` snapshot
Re-capture from the **production** `diagnoseRenderArgs(barn-program, rustic-pack)` so the snapshot
matches the serializer (no drift). Only `style_profile` (and any re-framed header) changes; the barn
program/palette body is identical.

### 5. `src/baml/fixtures/diagnose/prompt.golden.txt` — re-pin the rendered golden
Regenerate by rendering the new `inputs.json` through the new prompt template via the bridge. This is
FX-DB1's pin; it MUST be produced by the production render path, never hand-edited.

## Regeneration / ordering (matters)
1. Edit `department.baml` prompt + `diagnose.mjs` headers + doc-comments.
2. `npm run baml:gen` (regenerate `baml_client` from the edited `.baml`).
3. Regenerate `inputs.json` (production `diagnoseRenderArgs`) and `prompt.golden.txt` (bridge render) —
   a small throwaway node snippet, committed only as the two fixture files.
4. Update `diagnose.test.mjs` (DG5/DG7 comments + new DG8).
5. `npm test` green (pretest runs `baml:gen`; FX-DB1 must match the re-pinned golden).
6. Re-gate (metered): `GUARD_ONLY=1` probe → `VOTES=6 node …/style-agreement-run.mjs`; record JSON +
   verdict into the work artifacts. (Out-of-test; never autonomous-freeze.)

## The single risk the structure encodes
If the prompt re-frame **alone** under-moves the decomposition (judge still leans on the named pack
materials), the design's Approach-B fallback (a bounded explicit image-match gate) is the next step —
but that is a NEW decision recorded after the re-gate evidence, not built pre-emptively here.
