# T-071-01 — llm-material-map · Structure

The blueprint: files created/modified, module boundaries, public interfaces, ordering. Not code.

## Files

### CREATE — `baml_src/materialmap.baml`
The new multimodal BAML function, kept separate from the frozen build/judge/concept fns.
- `enum PlacementRule { Walls CornersEdges Roof Base Trim Openings }`
- `class MaterialRole { role string; block string; placementRule PlacementRule; rationale string }`
- `class MaterialMapResult { materials MaterialRole[] }`
- `function MaterialMap(design_doc: string, concept: image) -> MaterialMapResult { client ClaudeStub
  prompt #"…"# }` — prompt per design Decision 2 (job, anti-collapse directive, palette-prior-not-cap,
  placementRule vocabulary defs, real-survival-block requirement, `{{ concept }}`, `{{ design_doc }}`,
  `{{ ctx.output_format }}`). `@description` on `block` ("namespaced, real survival block id, e.g.
  minecraft:cobblestone").

### MODIFY (generated) — `baml_client/**`
Regenerated by `npm run baml:gen` after adding the `.baml`. Commit the regenerated client (the repo
tracks `baml_client/`). No hand edits.

### CREATE — `src/form/material-map.mjs`  (PURE core — the heart, unit-tested)
Imports: `tableKey`, `blockId` from `../sculptor/material.mjs`; `loadBlockTable` from
`../color/block-table.mjs`; `deltaE`/Lab access from the table rows (no new color math). No GL, no
I/O, no BAML, no Date/random.

Public interface (frozen objects where vocab-like):
```
export const PLACEMENT_RULES        // Object.freeze(["walls","corners-edges","roof","base","trim","openings"])
export const PLACEMENT_RULE_MAP     // { Walls:"walls", CornersEdges:"corners-edges", Roof:"roof",
                                    //   Base:"base", Trim:"trim", Openings:"openings" } + identity for kebab
export class MaterialMapError extends Error          // { code, …context } — for assertMaterialMap
export function normalizePlacementRule(raw) -> string|null      // PascalCase/kebab/space → kebab vocab, else null
export function normalizeBlock(raw) -> string|null             // → "minecraft:<bare>" via tableKey/blockId; null if not a string
export function isKnownBlock(raw, table?) -> boolean           // tableKey(raw) ∈ table.blocks
export function parseMaterialMap(rawObj, opts?) -> {           // rawObj = already-JSON-parsed {materials:[…]}
  map: Array<{role, block, placementRule, rationale}>,
  dropped: Array<{reason, entry}>,
  palette: string[],                                           // distinct blocks, namespaced (== paletteFromMap(map))
  stats: { in, kept, dropped, distinctBlocks, placementRules }
}
export function assertMaterialMap(map) -> void                 // throws MaterialMapError if empty/invalid
export function paletteFromMap(map) -> string[]                // distinct namespaced blocks, stable order
export function nearTonePairs(map, opts?) -> Array<[a,b,dL]>   // pairs of distinct blocks with ΔL ≤ tol (table Lab)
export function preservesDistinctGreys(map, opts?) -> boolean  // ≥1 nearTonePair in DIFFERENT roles → true
```
Internal helpers: `labOf(block, table)` (table lookup by bare key → `lab`), `dedupKey(e)` =
`block|placementRule`.

Boundaries: this module **validates membership** (table) but NOT artifact shape (that's
`src/artifact.mjs`, a different layer; the map isn't a DesignArtifact). It never calls a model. It
never *merges* by color — only drops invalid rows; near-tone preservation is emergent.

### CREATE — `src/form/material-map.test.mjs`  (unit tests, run by `node --test "src/**/*.test.mjs"`)
Covers (design Decision 6 trace): vocabulary freeze; `normalizePlacementRule` (PascalCase, kebab,
"corners-edges"/"CornersEdges", spaces, unknown→null); `normalizeBlock` (bare→namespaced, already-ns
passthrough, non-string→null); `isKnownBlock` with an **injected stub table** + the real table for
`stone_bricks`/`cobblestone`; `parseMaterialMap` happy path (gatehouse-like fixture: 4 distinct greys
kept), drop of unknown block (recorded in `dropped`, not thrown), drop of bad placementRule, dedup on
(block, rule), palette = distinct blocks, stats counts; `assertMaterialMap` throws on empty;
`paletteFromMap` order/dedup; `nearTonePairs` + `preservesDistinctGreys` true on a
stone_bricks+cobblestone fixture, false on a single-block map. **No live import** — never loads the
`.mts` bridge.

### CREATE — `src/form/material-map.mts`  (LIVE bridge — NOT unit-tested)
Copy of `src/sculptor/baml-review.mts` shape. stdin `{ conceptPath, docPath? }`:
- read+base64 the concept image, infer mediaType from extension;
- `doc = docPath ? readFileSync(docPath,'utf8') : "(no design document — infer materials from the concept image alone)"`;
- set `ANTHROPIC_API_KEY="baml-render-only"` if unset (render only), restore after;
- `req = await b.request.MaterialMap(doc, Image.fromBase64(mediaType, b64))`;
- extract text block + image block from `req.body.json().messages`;
- `requestTextWithImage({ prompt: textBlock, images:[{base64,mediaType}], model: PHASE1_MODEL_ID })`;
- fence/`{…}` strip → `b.parse.MaterialMap(cleaned)`;
- map each `placementRule` via `PLACEMENT_RULE_MAP` to kebab; stdout `{ materials:[{role, block,
  placementRule, rationale}] }`.

### CREATE — `benchmarks/sculpture/material-map.mjs`  (impure runner — writes saved maps)
Imports the pure core + `spawn` for the bridge. Constants: `SUBJECTS = [{key:"gatehouse", runDir:…015…},
{key:"cottage", runDir:…014…}]`. For each subject:
- resolve `concept.png` (required) + `design-doc.md` (optional);
- **live mode**: spawn `npx tsx src/form/material-map.mts` with `{conceptPath, docPath}`, capture
  `{materials}`; **`--offline` mode**: read the committed raw reply from
  `material-map/<subj>.raw.json` (if present) — re-validate without a live call;
- `result = parseMaterialMap({materials}, …)`;
- write `material-map/<subj>.json` = `{ schema:"material-map/v1", subject, generatedFrom:{concept,
  doc}, map, dropped, palette, stats, preservesNearTone: preservesDistinctGreys(map) }`;
- also persist the raw reply to `material-map/<subj>.raw.json` (so `--offline` is reproducible);
- console one-line summary (kept/dropped/distinct/nearTone) per subject.
Usage banner: `node benchmarks/sculpture/material-map.mjs` (live) / `--offline` (revalidate).

## Ordering of changes (matters)

1. `materialmap.baml` → `npm run baml:gen` (client must exist before the bridge imports it).
2. `material-map.mjs` (pure core) + `material-map.test.mjs` → `npm test` green (no live dep).
3. `material-map.mts` (bridge) — imports the regenerated client + the pure core's `PLACEMENT_RULE_MAP`.
4. Cottage `design-doc.md`.
5. `material-map.mjs` runner + `package.json` script.
6. Live run (metered) → write + commit the saved maps. (If live unavailable, `--offline` path +
   documented in progress/review.)
