## Falsifiable claim — verdict

The claim was: *`DiagnoseBuild` can reliably tag each item with `kind`, separating a wrong-material
`replace` from a right-material-missing-detail `add`, so the BO11 over-cap flips to `absent`.*

- **Plumbing PROVEN.** The schema carries `kind`; `b.parse` round-trips it (FX-DB2, CC1); the
  scoring core reads it with no edit (`itemStyleClass(wall) === "absent"` asserted end-to-end). The
  WALL item — structurally identical to a `replace` (present + missing both non-empty) — is tagged
  `add` and no longer caps; the ROOF wrong-material item stays `replace`. The two classes separate
  within a single critique on the canonical fixture.
- **The "fails if the judge can't separate consistently" clause is NOT answered here, by design.**
  The committed replies are author-chosen canonical specimens, not a live capture. Whether a real
  Layer-A judge *reliably* emits the right `kind` across a corpus is **T-170-02** (the live
  corpus-referee rerun, gated on this ticket). This ticket proves the contract carries the tag and
  the structural-rule blind spot is removed *when the tag is present*; it does not and cannot prove
  judge reliability. That distinction is the honest scope line — flagged, not papered over.
- **No scope leak observed.** The golden diff was the two intended regions only; CC2's empty-list
  and FX-DB2's vacuity guard held unchanged, so adding a required union did not perturb SAP
  behaviour. The "fixture re-pin reveals unrelated behaviour change" failure mode did not fire.

## Test coverage assessment

- **Strong where it matters:** the producer→consumer round-trip is asserted in one place (FX-DB2):
  parse emits `kind`, the BO11-shape item is `add`, and `itemStyleClass` reads it `absent`. BO8/BO11
  (pure, pre-existing) independently pin the kind→class mapping and the F1 correction. FX-DB1 pins
  the prompt bytes; CC1/CC2/CC3 pin parse accept/leniency/reject.
- **Gaps (acceptable, by scope):**
  1. No live-judge separability evidence — that is T-170-02's deliverable. The fixtures demonstrate
     the discriminator on hand-authored replies, which is necessary but not sufficient for the
     "reliably" half of the claim.
  2. `kind = "remove"` has no fixture exercising it through `b.parse` (the canonical replies use only
     `add`/`replace`). BO8 covers `remove` at the `itemStyleClass` layer, but no parse fixture emits
     it. Low risk (it is the same union member, parsed identically), but a `remove` specimen would
     make the parse coverage complete — a candidate for T-170-02's corpus or a follow-up fixture.
  3. The structural fallback for *untagged legacy critiques* is covered by BO8/BO11 (items with no
     `kind`), but there is no fixture of a real committed legacy critique re-parsed under the new
     schema. The schema change is additive and `kind` is required only going forward; legacy parse
     is not re-run here. If any pre-T-170-01 committed critique JSON is replayed through `b.parse`
     under the new schema, it would now lack the required `kind` — worth a check if such replay
     paths exist (none found in this ticket's scope; the only committed critiques are these
     fixtures, now tagged).

## Open concerns / handoff notes

- **Required `kind` and legacy data.** `kind` is required in the schema. Any code path that
  `b.parse`s a *pre-existing untagged* critique reply would now hit a required-field gap. The
  scoring core's `itemStyleClass` still has the structural fallback for *objects* lacking `kind`
  (e.g. a plain JS object), but `b.parse` over an untagged raw reply is a different surface. No such
  path exists among committed records (all are updated). Flag for T-170-02 if it loads any older
  raw reply.
- **T-170-02 is the payoff.** This ticket is deliberately the plumbing half. The epic's value lands
  only when the live judge run shows the tag separates the matched/wrong-style corpus that the
  structural rule collapsed (the E-40 finding: "style-distance term floors both, not craters"). If
  T-170-02 shows the judge *cannot* tag reliably, the honest outcome is "the tag is no better than
  the structural rule" — and that is a worthy, reportable result, not a failure to hide.
- **Nothing for a human to block on.** The change is additive, tested, byte-pinned, and scoped. No
  critical issues.
