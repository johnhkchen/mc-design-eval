# T-064-01 — Review: clean-color-materials

Handoff for a human reviewer. The ticket regains text→JSON colour cleanliness in the GLB-voxel build by
attacking the three documented noise sources: busy-block palette pollution, scattered diagonal gradients,
and `minRegion` eating real detail. Shipped across 7 commits (`6193d1a` → `c344674`); `npm test` is
**665/665 green**.

## What changed

### Data + primitive (Steps 1–2)
- **`src/color/block-table.mjs`** — `varianceOpaque(png, alphaThreshold)`: summed per-channel texture
  variance over the same opaque/first-frame pixels `meanOpaqueRgb` averages (`0` if <2 opaque pixels).
  `buildBlockTable` records a rounded `var` per block.
- **`src/color/block-lab-table.json`** — regenerated with the `var` field. `lab`/`rgb` verified
  **byte-identical** to the prior table (only `var` lines added). Variance distribution: min 0 / median
  672 / p90 3859 / max 15253.
- **`src/color/cielab.mjs`** — `nearestFlat(targetLab, palette, {lambda, metric})` and `FLAT_LAMBDA = 0.10`.
  Scores `ΔE + λ·sqrt(var||0)`; returns `{key, deltaE, lab}` where `deltaE` is the **true** ΔE (callers that
  report drift stay honest). Palette entries without `var` degrade to plain `nearestLab` — back-compatible.

### AC#1 — variance-aware palette
- **`src/form/glb-voxel-build.mjs`, `material-clean.mjs`, `palette-extract.mjs`** — palette builders carry
  `var` on entries (`paletteFromManifest` / `blockPaletteFromTable` / `extractTexturePalette`).
- **`src/form/material-segment.mjs`** — `fillRegion` / `bandRegion` route their picks through `nearestFlat`,
  so within the design-doc set a flat block beats a busy one of comparable ΔE.
- **`src/form/palette-augment.mjs`** — gated secondary uses `nearestFlat` AND a hard `varCeiling = 1200`:
  a candidate table block above the ceiling cannot be added regardless of fit. Calibrated so
  coral_brain (1363) / mycelium (2483) / quartz_ore (7114) are excluded while matte concrete/terracotta/
  planks/stone (≤ ~700) pass. `meanSnapBefore/After` keep `nearestLab` (honest drift reporting).
  **Design-doc blocks are never dropped** — the ceiling gates only the secondary the model never asked for.

### AC#2 — true-axis gradient banding
- **`material-segment.mjs`** — `gradientDirection(region, cellCoords, labs)` fits `L* ≈ α·i+β·j+γ·k+δ` by
  3×3 normal equations; the normalized `(α,β,γ)` is the direction colour varies fastest along. `bandRegion`
  projects each cell onto it (lo/hi/extent/position), so a diagonal gradient bands monotonically instead of
  scattering across two cardinals. Singular `XᵀX` (degenerate/planar region) → falls back to the cardinal
  `gradientAxis` path, which stays exported for that fallback + its test.

### AC#3 — minRegion noise-vs-intent (+ keepFloor dual-gate)
- **`material-segment.mjs`** — `absorbSmallRegions` gains `{absorbDE = 22, tinyFloor = 2, keepFloor = 8}`.
  A region smaller than `minRegion` is kept as deliberate detail only when it is **colour-distinct**
  (bestΔE > absorbDE) **and** a real feature (≥ keepFloor cells). Everything else — tiny flecks
  (≤ tinyFloor), near-in-colour regions, or distinct-but-sub-feature snap-flecks (3–7 cells) — is absorbed.
  `keepFloor` was the koi-speckle refinement (commit `1518c2d`); the single-distinctness gate alone left a
  long tail of distinct 3–7 cell flecks that inflated speckle without enriching the palette.

### AC#5 — applied ×7
- **`benchmarks/sculpture/e18-build/*`, `e18-remeasure.{json,md}`** — regenerated by a live sweep
  (scale 32, headless GL + dwebp) against the full stack. See `progress.md` for the before/after table.

## Open concerns / flags for a human

1. **value ΔE rises vs R2 (6–21 across subjects).** This is the known **ablation tautology**
   (`ablation-value-de-tautology` memory): R2's value ΔE is 0 *by construction* because it is the
   value-true baseline measured against its own palette. The E18 numbers are the honest cost of snapping to
   the design-doc manifest. Worst cases (moai 20.85, koi 17.55) are the subjects whose design-doc palette is
   smallest/most saturated — not a regression introduced by flat-preference, but worth a human eye on the
   moai/koi renders to confirm the value read still reads. **Not a blocker; flagging for visual sign-off.**
2. **`keepFloor = 8` is scale-32-calibrated.** It assumes a legitimate feature is ≥8 voxels. At other scales
   the floor should scale with voxel count; today it is a fixed const in `SEG_DEFAULTS`. If E-21 / T-068
   pushes to higher-res builds, revisit whether `keepFloor` should be a fraction of subject extent.
3. **`varCeiling = 1200` admits `dead_fire_coral_block` (var 1051) as a SECONDARY on mushroom.** This is
   the concrete instance of the ceiling's soft spot: dead_fire_coral is NOT in the mushroom design-doc
   manifest ({red_concrete, bone_block, moss_block, white_concrete}); it is a *gated secondary* the
   augmenter inserted. It is strictly better than before — it displaced the busier `dead_brain_coral_block`
   (1363) / `mossy_stone_bricks` (1594) the prior build used, so the manifest is flatter and the three
   named busy blocks are gone. But it is a mildly-textured (var 1051) block entering by augmentation, not a
   pure matte. The ceiling is honest (1051 < 1200), yet if cleaner reads matter more than this secondary's
   colour fit, a tighter ceiling (~800) would force it to a matte block. **Flagging as the one ceiling
   judgement call for human sign-off — keep at 1200, or tighten if the mushroom-cap read suffers.**
4. **form IoU regressions (moai −0.17, dancing −0.10 vs R1) are pre-existing**, owned by the thin
   voxelizer / segmentation style, not this ticket. T-064 is occupancy-neutral. Out of scope here; tracked
   under the form-routing work (T-065).

## Bottom line

All five ACs met, 665 tests green, the busy-block / scatter / detail-loss trio is closed, and the live
sweep shows the cleanliness win (off-palette → 0, speckle below R2 everywhere) with no manifest pollution.
The one item needing human judgement is the value-ΔE-vs-R2 read on moai/koi, which is a measurement
tautology rather than a quality regression.
