# T-187-01 — STRUCTURE (file-level change map)

The blueprint: which files change, the new strings, the regeneration order, what stays frozen. No new
modules; no schema change; no scoring-core edit. Mirrors the T-186-01 structure exactly (same seam).

## Files MODIFIED

### 1. `baml_src/department.baml` — the `DiagnoseBuild` prompt (the MEDIUM tolerance, D1+D2)
The load-bearing edit. Append a VOXEL-MEDIUM clause AFTER the existing `CONCEPT-CONDITIONAL` sentence
(keep that sentence), before "Tag each item with the department that owns it":
- The build is **VOXEL (Minecraft blocks at finite resolution)**; the concept may be **smooth painted
  art**. Blockiness, stair-stepped curves/diagonals, and the coarser block-texture palette are the
  MEDIUM, not divergence (D1).
- Judge **same-thing-ness at block resolution** (same form-class, same material family, same feature).
  Do **not** tag `replace` and do **not** raise severity to `major` merely because an element is
  blockier/coarser than the smooth concept.
- Ornament **finer than the block grid can resolve** is below the medium's resolution — absence of it is
  not a divergence (D2).
- **Reserve `replace`/major** for an element depicting a GENUINELY DIFFERENT thing (different
  form-class, different material family, or absent design element) — the explicit decoupling guard so
  wrong-picture builds are NOT forgiven.
- **Do NOT** touch `RouteCritique`, the enums, or `Critique`/`CritiqueItem`. Keep the `kind`/`severity`
  schema lines. The `style`/`palette_block`/`style_profile` slots are unchanged (their CONTENT for
  style_profile re-frames in `diagnose.mjs` below).

### 2. `src/workshop/diagnose.mjs` — sharpen the `styleProfileBlock` header (the material anti-leak, D3)
- `styleProfileBlock({pack})`: extend ONLY the header line. Current head:
  `"THE … PACK'S NAMING VOCABULARY (materials & idioms available to DESCRIBE the build and its concept —
  NOT the standard; the CONCEPT IMAGE is the standard. A build that matches its concept image is correct
  even if its materials differ from this list):"`
  Add the **material** sharpening (D3): the vocabulary's materials are **never the EXPECTED material** —

  CORRECT (`match`), not `replace`. (One appended clause; the role→block / idiom BODY is unchanged so
  DG5/DG7 hold.)
- Update the doc-comment on `styleProfileBlock` / `diagnoseRenderArgs` to name the T-187 material
  anti-leak (cite E-47 / S-187) alongside the existing T-186 vocabulary frame.
- **Signature unchanged**: `styleProfileBlock({pack}) → string`,
  `diagnoseRenderArgs({program, pack, azimuths, maxItems}) → {…same keys…}`.

## Regeneration / ordering (matters — same as T-186)
1. Edit `department.baml` prompt (medium clause) + `diagnose.mjs` header (D3) + doc-comments.
2. `npm run baml:gen` (regenerate `baml_client` from the edited `.baml`).
3. Regenerate `inputs.json` (production `diagnoseRenderArgs`) and `prompt.golden.txt` (bridge render) via
   a small throwaway node snippet (committed only as the two fixture files).
4. Update `diagnose.test.mjs` (add DG9) + `fixtures.test.mjs` (FX-DB1 medium-clause regex).
5. `npm test` green (pretest runs `baml:gen`; FX-DB1 must match the re-pinned golden; DG1–DG9 pass).
6. Commit the seam change (one feat commit).
7. Re-gate (metered): `GUARD_ONLY=1` probe → `VOTES=6 node …/style-agreement-run.mjs`; record JSON +
   verdict into `progress.md` + `RE-GATE.md`. Out-of-test; never autonomous-freeze.

## The single risk the structure encodes
If the medium clause + D3 **alone** under-move the decomposition (the +6 gap is irreducible, or matched
and wrong both lift), Approach-B (a bounded explicit image-match gate) is the recorded fallback — a NEW
decision after the re-gate evidence, not built pre-emptively. The structure keeps the change reversible:
every edit is additive at the seam; rollback is `git revert` of the feat commit + restoring the prior
golden/inputs. The gate, scoring core, and `measurements/` are never touched.
