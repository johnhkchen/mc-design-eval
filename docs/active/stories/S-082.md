## Background (self-contained)

Epic **E-23**, the **agentic-engineering** story. Because the 2.5-D layer scopes each op to a *view*, many
sub-tasks become narrow enough for a **lighter, cheaper model tier** — "find the roof cells that need
patching," "mark the hollowable interior" are small, well-posed visual calls. This is where the project
starts doing real multi-model agentic engineering: scope a task tightly enough that a small model suffices,
and escalate to a stronger tier only for judgement that demonstrably needs it.

## Goal

1. A **per-op model-tier seam** over the **`claude -p` subscription shim**: an op declares the tier it needs
   and the shim is invoked with the matching `--model` override. `config.mjs` single-sources the tier IDs
   (light = Haiku, strong = the pinned default). **The metered API key must never enter this path** — lighter
   models are still the subscription, just a smaller `--model` (the standing Phase-1 invariant).
2. **Exemplar light-tier detectors** proving the pattern: a **roof-patch detector** (which roof cells read
   wrong / need patching) and the **hollowable-mass detector** (S-080's mark), both scoped to a projected
   view and run on the light tier.
3. The **scoping principle, recorded**: for each op, the tier chosen + why (what made it narrow enough for a
   light model, or why it needed the strong one). A short rubric: narrow detector / classification on a
   single view → light; cross-view judgement, authoring a generator, material zoning → strong.

## Builds on
