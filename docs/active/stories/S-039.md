## Goal

Epic **E-14**, the keystone seam. Build the **shared color contract** both downstream stages consume:
a pure resolver that takes the design doc's proposed palette (named blocks, intuited by the model) and
**snaps each to the block-Lab table**, returning every block's *true rendered value* — and, when the
doc names a non-cube / biome-tinted / imaginary block, the **nearest real full-cube block** instead.

This is the fix for the root cause E-13 named: the design doc picks blocks by *name*, the concept
previews *hue*, and the render exposes the *true value* — three different things. Pinning all three to
the block-Lab table up front makes the palette honest *before* either stage uses it.

## Builds on

- E-10 color engine: `src/color/block-table.mjs` (`loadBlockTable`, the 305-block Lab table),
  `cielab.mjs` (`nearestLab`, `srgbToLab`), `palette-extract.mjs` (`resolvePalette`).
- The vConcept design-doc stage (`src/sculpture.mjs` `composeSculptureDesignDocPrompt`) as the producer
  of the named palette this resolver consumes.

## Run-the-test ticket

- `T-039-01` — implement + unit-test `resolveValueTruePalette`; prove it snaps imaginary/non-cube names
  to nearest real blocks and surfaces true value; produce a value-honest palette card.
