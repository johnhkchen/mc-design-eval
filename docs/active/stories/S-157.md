## Background (self-contained)

Epic **E-37**. The consolidation (S-154..S-156) cleans the current state *once*; without enforcement it
re-sprawls, because **autonomous coding runs start with thin context** and documentation informs but
does not bind them. The project already trusts **structure over discipline** for the build (the 4-can
palette, the registry-as-only-door, the workshop that *cannot* call the judge). This story points that
lens at the codebase topology: make the wrong organizational move **structurally impossible**.

## Goal

The five anti-confusion guardrails, as enforcement:
1. **Authoritative map, kept current.** `STRUCTURE.md` (Stage → owning module → artifact → entry point
   → archived) is the single source of truth; a test fails if a stage's module is absent from the map
   or the map names a module that doesn't exist. (Any stage-changing ticket updates it in the same
   commit — the rule, plus the test that catches a stale map.)
2. **Location encodes status** (established in S-155) — guarded here: a **draft written outside
   `builds/`** fails; the pin-guard allowlist *is* `measurements/` + ratified `packs/`.
3. **No live-spine import of `_archive/`** — a conformance test fails the build on any such import.
4. **One entry point** — a test fails if a second "build a subject" chain entry point appears.
5. **Done = delivered, not compiled** — a creation run's completion requires the canonical artifact
   regenerated + **rendered beside the concept** (E-36); + **replace-don't-accrete** and a checkable
   **lisa claim** so a second thread sees the first ([[lisa-same-ticket-concurrency]],
   [[ticket-double-dispatch]]).

Each is a test that goes **red on violation**, not a doc that gets ignored.
