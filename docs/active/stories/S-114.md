## Background (self-contained)

Epic **E-29**. The church's first-ever gate run (T-110) returned three judged views and one **unparsed
judge reply** at 225° — and the aggregate became **REFUSAL (unparsed:-x-z)**. The no-re-roll rule
(correctly) forbade an inline retry: re-rolling *verdicts* is how gates get gamed. But a malformed
reply is not a verdict — treating it as one lets a single transport/format hiccup poison a milestone
and (worse) creates pressure to bend the no-re-roll rule ad hoc. The instrument needs the distinction
made structural.

## Goal

A **parse-failure policy at the judge seam** (E-29 Rule 3): judge replies are schema-validated; a
malformed reply triggers a **bounded re-ask** (declared limit, same prompt, same pinned model) with
**every reply committed** — the malformed ones included, as the audit trail; aggregate REFUSAL only
when the re-ask budget is exhausted. **Verdict re-rolling remains impossible**: a reply that parses is
final, whatever it says; the policy never re-asks a parsed verdict. The church 225° case is the
regression fixture; thresholds/azimuths/judge contract untouched (this is I/O handling, not gate
semantics).
