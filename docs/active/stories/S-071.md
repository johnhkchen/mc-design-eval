## Background (self-contained)

Epic **E-21** fixes a failure colorimetry can't: mean-color CIE-Lab matching **collapses stone brick and
cobblestone** (near-identical mean color, but the concept used them as distinct materials). Material
identity is **semantic**, not colorimetric — so this story has a multimodal LLM **look at the concept** and
name the materials by intent.

The LLM (which can SEE the concept image, like the build/judge stages do) returns a structured **material
map**: the distinct materials the concept uses, each with the **real block** that realizes it and a
**placement rule** (which feature/region it belongs to). Crucially it may include **near-tone-distinct
pairs** (stone_bricks for walls + cobblestone for corners) — exactly what colorimetry merges. This is the
"LLM defines the style" step.

## Goal

A multimodal BAML function (sibling of the build/judge fns) that takes the **concept image + design doc**
and returns a validated material map: `[{ role, block, placementRule }]` over real survival blocks
(constrained to the schema's block vocabulary; the design-doc palette is the prior, but near-tone-distinct
architectural materials are allowed and encouraged where the concept shows them).

## Builds on

- The multimodal seam (`src/sdk-binding.mjs`) + BAML (`baml_src/`, the concept/judge fns as the pattern) +
  the concept image (`runs/<run>/concept.png`) + design doc.
- The artifact block vocabulary (`src/artifact.mjs` / `minecraft-data`) to validate the chosen blocks.

## Run-the-test ticket
