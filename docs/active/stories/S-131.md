## Background (self-contained)

Epic **E-32**. The model is good at decomposition — breaking a style concept into the components it
needs — and AI coding (lisa) is good at implementing well-specified reusable components. What's
missing is the conveyor between them: today, new build techniques get designed ad hoc inside epic
emergencies. The factory turns design work into a **managed backlog**: style concept + registry state
in → **brush work-item drafts** out, each self-contained enough that a promoted draft runs through
lisa without rework. The runaway risk is handled structurally (E-32 Rule 3): drafts land **outside
lisa's scan dirs**; promotion by a human (or the planner under explicit user direction) is the only
path to scheduling.

## Goal

The **decomposition function** (BAML, S-129): given a formed style (S-130) and the current registry
(S-128), emit **brush work-item drafts** into `docs/active/backlog/` — each with: brush name +
purpose, parameter schema sketch, composition notes (what it chains with), test plan, preview
subject, and the lisa-shaped ticket skeleton (Context/AC in house style). Plus: **duplicate
detection** against the registry (never request an owned brush; suggest parametrization of an
existing one instead), and the **promotion flow documented** (backlog → human review → ticket).

## Builds on

- S-129 decomposition function; S-128 registry (the dedup target + the contract drafts must satisfy);
  the house ticket conventions (self-contained Context + binding ACs — the drafts must match what
  lisa runs well).

## Run-the-test ticket

- `T-131-01` — the factory + backlog dir (outside `.lisa.toml` scan) + dedup + promotion doc; run
  against the milestone style: drafts generated, ≥1 promoted by hand and executed by lisa cleanly
  (the rework measure recorded).
