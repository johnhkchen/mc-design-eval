## Background (self-contained)

Epic **E-22**. The Minecraft build should look like its references (the concept image + the GLB mesh
render). On the scale-64 gatehouse the build is **clean by every block metric** (`speckle: 0.001`,
`distinct: 4`, `offPalette: 0`; 2.0% surface neighbor-disagreement) yet the render reads as grey static.

**Root cause (diagnosed, not theorized).** At scale 64 the building spans ~64 voxels framed into ~400px of
a **512×512** image → **~6 px per block**, while each Minecraft block texture is **16×16**. The viewer atlas
minifies with `minFilter = THREE.NearestFilter` and **no mipmaps** (`worldrenderer.js:91-92`), and the
renderer is `new THREE.WebGLRenderer({ canvas })` with **no antialiasing** (`render/src/render.mjs:75`).
Point-sampling a busy 16px texture down to 6px makes adjacent screen pixels grab unrelated texels →
**minification aliasing** → static. The lens is broken; the build is fine.

## Goal

Make a clean build **photograph clean at the high scale**. Fix the render lens so the texture static
disappears — **without changing the build** and **without lowering the scale** (Rule 3: shrinking the build
to dodge aliasing is a cheat, not a fix). The render must stay **deterministic and comparable** (E-02): two
builds are still photographed identically.

Two levers (use either or both; whichever clears the static cleanly and stays in our own code):
- **Supersampling** — render at N× the 512² contract (e.g. 1024² or 1536²) and **box-downscale** to 512².
  Averages many texels per output pixel → kills minification aliasing *and* geometry-edge aliasing. Fully
  owned in `render/src/render.mjs`; no `node_modules` patch.
- **Mipmapped minification** — set the atlas `minFilter = NearestMipmapLinearFilter` + `generateMipmaps`,
  keeping `magFilter = NearestFilter` so the crisp pixel-art look survives when blocks are large. This is
  what Minecraft itself does; it lives in the viewer atlas, so it needs a post-load hook on the texture
  (not an edit to `node_modules`).

## Builds on
