## Context (self-contained)

Epic **E-41**. The whole fix: add a judged `kind` discriminator to `CritiqueItem` so the style-distance
term stops inferring style-class from string emptiness (the E-40 over-cap). Blueprint:
`docs/active/work/T-168-01/schema-feedback.md`. The scoring core (`itemStyleClass` in
`src/workshop/bakeoff-score.mjs`) already reads `kind` (`replace→wrong-style`, `add→absent`,
`remove→match`) before its structural fallback — so this story only needs Layer A to *emit* it, then proves
the result.

Two steps: (T-170-01) the schema field + prompt + re-pin + the BO11 unit-level flip; (T-170-02) the live
corpus re-run that shows the over-cap is gone and reports whether the crater separates.

## Falsifiable claim (anti-hedge — lead with how it fails)

A judged `kind` makes the term cap *only* genuine wrong-style (`replace`), not incomplete-but-right (`add`)
— so the corpus's truly-matched-and-faithful states recover above the floor while genuine wrong-style stays
capped. **It fails if:** `DiagnoseBuild` tags `kind` unreliably (wrong-material vs missing-detail confused →
report the confusion, the tag earns nothing); OR matched-faithful states still floor after the tag (the cap
logic itself is wrong, not the classifier); OR there is **no** materially-faithful matched build in the
corpus to demonstrate the crater (expected — that absence *is* the E-42 hand-off, reported not hidden).
