## Background (self-contained)

Epic **E-19**, a documented design-debt cleanup. E-18 found that thin-feature-preserving voxelization
(`voxelizeGlbThin`, T-059) **lifts thin subjects** (bow-and-arrow form IoU 0.473→0.526, koi up too) but
**over-thickens already-solid forms** — the combined build applied it to **all 7**, regressing solid
subjects (dancing-man form IoU **−0.10**, also heart/mushroom/pineapple/moai) and ~**2× occupancy** on
subjects that don't need it. The form-type-routing rule was **named but never wired** (T-061 review
concern #4): *thin/organic → thin-preserve; solid/bulky → plain voxelize.*

This story wires it: a per-subject switch so each subject uses the voxelizer that helps it. It also reduces
spurious bulk (a cleanliness win — the over-thickened shell on solids adds material that isn't in the
reference).

## Goal

A per-subject routing switch: `voxelizeGlbThin` for the **thin** subjects (bow-and-arrow, koi), plain
`voxelizeGlb` (E-16) for the **solid/bulky** ones (heart, mushroom, pineapple, moai, dancing-man) — a
small subject-keyed config, not a new algorithm. Form IoU recovers on the regressed solids; occupancy
drops back where thin wasn't needed.
