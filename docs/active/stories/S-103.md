## Background (self-contained)

Epic **E-27**. The pipeline's surfaces that look right are the ones it *re-authors from geometry*; the
ones that look wrong are inherited raw from the decimated mesh. To re-author the major masses, the blob
must first become **named components with geometry**: which cells are the roof (and its planes), which
are wall slabs, which are attached masses (a church tower vs its nave), where the opening groups sit.
The structural read already supplies floor lines, wall fields, openings, and a roof region — but as
*per-cell* classifications over noisy occupancy, not as component *geometry* downstream code can fit
parameters to.

## Goal

A **component decomposition** of the (regularized) shell: segment into named structural components, each
with explicit geometry — roof planes (normal, extent, eave edge), wall slabs (plane + bounds), attached
masses (separable bounding volumes + junction), opening groups — derived from the structural read + the
GLB, output as a **component record** that is the single contract S-104/S-105/S-106 consume (E-27
Rule 4). Pure, deterministic, unit-tested on synthetic shells; subject-agnostic.

## Builds on

- `src/view/structural-read.mjs` (floor lines, wall fields, openings, roof region — the per-cell
  primitives this lifts into geometry); the GLB (plane-fit reference); S-102's regularized shell (a
  cleaner substrate to segment, though decomposition must tolerate raw shells too).

## Run-the-test ticket

- `T-103-01` — decomposition core + component-record schema; run on cottage (2 roof planes + walls +
  chimney), gatehouse (walls + roof + arch opening), church (tower + nave + their roofs) — components
  named and visualized; record committed per subject.
