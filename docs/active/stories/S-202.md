## Context (self-contained)

Epic **E-52**, the unblocker (highest-leverage of the three geometry fixes). The E-49 capstone (T-201) showed:
after `relief_walls`, `closureOf` collapsed **1.000 → 0.068** though the shell is physically intact and
relief's own `recessClosureGuard` reported "closure held." Root cause, read not guessed: `eaveRingClosure`
(`src/view/wall-generate.mjs:275`) folds **every** band column `(x,z)` into the perimeter, so the **224 proud
quoins + 106 plinth cells** that `relief_walls` stands *outside* the wall plane — the geometry that makes the
wall read as construction — expand the sampled ring and crater the metric. The climb's own gate then turned
against the build (round 5 re-picked `close_shell`, which no-op'd because the proud columns also defeat
footprint registration), and on a longer budget it **oscillates**: detail → "shell reopened" → close no-op →
detail. The form-readiness signal must be made **invariant to proud detail.**

The fix: measure closure on the **wall plane / footprint** (the structural envelope), not over all band
columns — proud quoins/plinth sit outside it and must not count as "open."

## Falsifiable claim (anti-hedge — lead with how it fails)

A wall-plane/footprint closure metric stays **high** through the real T-201 relief pass (the relief build reads
closed, so detail stays unlocked and the climb stops oscillating) **and** still reads **low** on a genuinely
reopened shell (a real hole). **Fails if:** the fix over-corrects — measuring on the plane makes it **blind to
a real reopened shell** (a true hole now reads closed → the metric is wrong the other way; the regression
fixture is what guards this); or proud detail can't be cleanly separated from the wall plane on this geometry
(the plane isn't well-defined → name it); or the change shifts the form-ready gate threshold (0.9) calibration
(re-pin with a failing test).
