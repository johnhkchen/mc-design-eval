## Background (self-contained)

Epic **E-24**. The cottage plaster block (`white_terracotta`) renders **pink**, not the concept's warm
**cream** — the role's block was chosen by **name**, never validated for **value** against the concept. The
judge named the residual `palette@upper`. This is the [[value-true-palette-codesign]] gap: a block named for
a material can still be the wrong value ([[concept-image-not-color-value-preview]]).

## Goal

Select/validate each material role's block for **value-faithfulness** against the concept swatch in
**CIE-Lab** (the E-14 engine): sample the concept region for that role, find the nearest **value-true**
survival block within the role's material family, and prefer it over a name-match that drifts in value. So
plaster resolves to a true cream (not pink), roof to the right brown, etc.

The map's named block is the **prior**; the value gate picks the faithful block (within the role's family,
staying on the design-doc palette discipline — not a return to full-table snap).

## Builds on

- The E-14 CIE-Lab value-true engine (`src/color/block-table.mjs` / palette), the E-21 material map (role →
  candidate block), the concept image (the value reference), the per-face resemblance gate (E-22).

## Run-the-test ticket

- `T-086-01` — implement value-true block selection per role (sample concept swatch → nearest value-true
  block in family → prefer over a drifted name-match); run on the cottage; record plaster `white_terracotta`
  → the truer cream block, with the value-ΔE before/after. Pure selection unit-tested.
