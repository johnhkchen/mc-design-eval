## Goal

Epic **E-14**, the concept end of the co-design loop. Make Nano-Banana generate the concept **against
the real block values**, not its own imagined hues — closing `[[concept-image-not-color-value-preview]]`
(the concept blocks hue but not value; a named block can render far darker than the concept showed).

Add a `SculptureConceptPrompt` **`.v2` variant** (kept SEPARATE from the frozen `.v1`, so E-13's runs
stay reproducible) that consumes the **value-true palette** (S-039) and **attaches a rendered swatch
grid of the actual blocks** as a multimodal input. The concept is then grounded on what the blocks
*really look like*, so it stops over-promising — it becomes an honest build target.

## Builds on

- S-039 `resolveValueTruePalette` (the contract) + the swatch grid it produces.
- `baml_src/conceptart.baml` `SculptureConceptPrompt` (the `.v1` to clone, not edit), the
  `benchmarks/sculpture/baml-concept.mts` render path, and `src/nano-banana.mjs` (multimodal attach).

## Run-the-test ticket

- `T-040-01` — add the `.v2` palette-aware concept variant + swatch-grid attachment; A/B its concept vs
  the E-13 `.v1` concept on the sculptural subjects; record which previews value more honestly.
