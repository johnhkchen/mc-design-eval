## Context

Epic E-03 / spec §7 (archetype 3: multimodal enhanced). Extend the single live seam (`src/sdk-binding.mjs`) so a trial turn can send the model a **rendered WIP image** plus text and get back a validated artifact — the mechanism that lets the model *see* its build and revise it.

Default path is the `claude -p` shim (spec §4). Research and implement image input on that path: the most likely route is `claude -p --input-format stream-json --output-format stream-json`, feeding a user message whose `content` carries an image block (base64 PNG) alongside the text. (Documented alternative if CLI image input proves unworkable: have the render MCP tool return the image as an image content block via `--mcp-config`, so the model sees it when it calls the tool.) Whatever the mechanism, preserve the existing contract: stream every message to `onMessage`, re-validate the emitted artifact against the schema, and surface a clear error on failure. Keep the text-only `requestDesignArtifact` working unchanged.

## Acceptance Criteria

- [ ] A new seam function (e.g. `requestDesignArtifactWithImage`) accepts a prompt **and** one or more PNG images and returns the validated artifact + terminal result, via the `claude -p` subscription path.
- [ ] The image is delivered to the model as visual input (confirmed by a live round-trip where the model's response references what it saw).
- [ ] The full message stream is still passed to `onMessage`; per-turn token usage (incl. image tokens) remains capturable by the runner's `tallyUsage`.
- [ ] The existing text-only path and all current tests are unaffected; new pure helpers (message/content shaping) are unit-tested offline.
