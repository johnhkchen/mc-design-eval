## Context (self-contained)

Epic **E-27** / Story S-105. Roof-as-program (T-104) is one instance of the general capability: **clean
voxel constructs generated from fitted parameters** — built the way a player builds, not sampled from a
mesh. Witnessed candidates beyond the roof: the **gatehouse arch** (present in the concept, degraded
through the sampled pipeline), church window heads, and slope/edge transitions generally. The
fixture-state path is proven (T-097: stairs/slabs/trapdoors render with correct orientation); the
*generators* don't exist.

## Acceptance Criteria

- [ ] **Three pure generators**, each spec→state-correct placements, exhaustively unit-tested across
      orientations: (a) **stair run** — a slope segment in any cardinal direction, both windings,
      correct `facing`/`half` states; (b) **slab step** — half-block transitions (top/bottom states);
      (c) **arch** — spring line + radius + depth fit to an opening group (T-103), voxel-circle
      construction, jamb/head cells identified for the dressing pass.
- [ ] **Fit-from-component seam**: each generator's spec is produced by fitting against the component
      record + GLB (fit error recorded), same tolerance-or-named-fallback contract as T-104 (E-27
      Rule 1).
- [ ] **Applied under the cage** (T-102) where the component record names a candidate: the **gatehouse
      arch** rebuilt as a generated arch; **church openings** get arch/flat heads per their geometry.
      Before/after renders; render `unmapped` empty; closure + dressed-opening semantics preserved
      (T-097/E-25 integration case unit-tested).
- [ ] Generators are subject-agnostic library code (the construction vocabulary future epics draw
      from); documented; no subject-specific constants; `npm test` green.
