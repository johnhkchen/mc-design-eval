## Context (self-contained)

Epic **E-39** / Story **S-165**. The within-family blindness can only be *disproven* if ≥2 styles have
genuinely different `expected`. This ticket supplies a **second, non-rustic** style as a Layer-A `expected`
profile (roof/wall/opening expectations that are NOT a rustic reskin) — and a concept to test it against.

## Falsifiable claim (anti-hedge — lead with how it fails)

A non-rustic style profile makes Layer A describe a materially different `expected` (e.g. a different roof
idiom, a different wall grammar, different opening treatment) such that a rustic build critiqued against it
reads as *wrong-style* — the signal S-166's fixture needs. **Fails if:** the only `expected` we can author
still resolves to rustic idioms (the idiom-registry/grammar can't express a second language) → **that is the
finding**: real style differentiation needs a grammar-expressing schema + new idioms, a generator epic. Name
it; do not fake breadth with a recolor.

## Acceptance Criteria

- [ ] A second style available to Layer A as an `expected` profile whose roof/wall/opening expectations
      differ in *grammar*, not just block choice; a concept image to test against (existing or sourced).
- [ ] Fixture: a rustic build critiqued under the second style produces wrong-style `missing`/`present`
      items (not just "wrong colour").
- [ ] **Recorded honestly:** if the second style can't be expressed beyond rustic idioms, say so and scope
      the generator epic — that negative result is the point, not a failure to hide.
- [ ] `npm test` green; frozen instrument untouched.

## Notes
- This is the breadth gate the whole epic leans on. A reskin masquerading as a second style would make
  S-166 pass meaninglessly — the bar is *different grammar*.
