## Context (self-contained)

Epic **E-21** fixes the failure that mean-color CIE-Lab matching **collapses stone brick and cobblestone**
(near-identical mean color; a *deliberate* concept distinction). Material identity is **semantic** — so a
multimodal LLM **sees the concept** and names materials by intent. This ticket is that "define style" step.
(Runs after E-19's cleanup — clean regions first, then the right material per region.)

## Acceptance Criteria

- [ ] A **multimodal BAML function** (sibling of the build/judge fns; the model receives the **concept
      image + design doc**) → a structured **material map**: `[{ role, block, placementRule }]`, where
      `block` is a real survival block and `placementRule` names the feature/region (walls / corners-edges
      / roof / base / trim / openings).
- [ ] The map **preserves near-tone-distinct materials** where the concept shows them — e.g. on the
      gatehouse it returns **stone_bricks (walls) AND cobblestone (corners/buttresses)** as separate roles,
      not one merged grey block.
- [ ] Blocks validated against the artifact vocabulary (`src/artifact.mjs` / `minecraft-data`); the
      design-doc palette is the prior but the map is **not capped to it** — the LLM may include any
      material the concept shows, **adding blocks back** the tight palette dropped (concept-justified;
      near-tone architectural materials encouraged). The map defines E-21's allowed palette.
- [ ] Run on the gatehouse + cottage concepts; the maps saved (`benchmarks/.../material-map/<subj>.json`).
- [ ] Pure parse/validate logic unit-tested (the live multimodal call is metered); `npm test` green.
