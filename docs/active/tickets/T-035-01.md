## Context

Epic E-13 / story S-035. Implement the `vConcept` **sculpture mode** — term → 3-D voxel object — reusing
the proven pieces, adding only the generalizations:

1. **Imagined design doc** — a subject-parameterized prompt that writes a finalized design doc for an
   *object* (form, proportion, palette, motifs) from a term, no reference photo. Generalize the
   design-doc patterns (keep palette discipline); it must describe a freestanding object, not a facade.
2. **3/4 sculpture concept** — a `SculptureConceptPrompt` (new BAML fn, or generalize `FacadeConceptPrompt`):
   "concept art of a Minecraft-block **[subject]** as a single isolated object, 3/4 view, on solid black,
   block-scale detail for a ~`scale`-block build" — doc-only (no reference image). Via the existing
   nano-banana client.
3. **3-D build (single-view grounded)** — the existing multimodal build (`requestDesignArtifactWithImage`)
   grounded on the **one** 3/4 concept, but with a **sculpture build prompt + task**: a freestanding 3-D
   voxel object occupying x/y/z (NOT facade FACES-+Z + relief-only). The back/sides are the model's
   imagination from the single view — a known limit (and the case for image→3D), documented.
4. **`--scale` parameter** — target build size in blocks (e.g. 16/32/48); threaded into the doc/concept/
   build prompts.
5. **Render 3/4 + turntable** — render the result via the orbit rig (3/4 still + a rock turntable), not
   the head-on facade camera.

Wire as a runnable approach: `--subject "<term>" --scale <N>`. Reuse, don't fork, wherever possible.

## Acceptance Criteria

- [ ] A `vConcept` approach runs end-to-end from a term: `--subject "moai" --scale 32` → design doc →
      3/4 concept image → a 3-D `DesignArtifact` (full object, not a facade) → a 3/4 render + a rock
      turntable. Smoke it on ONE subject.
- [ ] The sculpture concept prompt + the sculpture build prompt/task exist and are object-oriented (no
      facade "front elevation / relief into −Z" assumptions); `--scale` is honored.
- [ ] The single-view limitation (back/sides imagined) is documented in the approach.
- [ ] Existing tests stay green; any new pure logic (e.g. scale wiring) is unit-tested. `npm test` green.
