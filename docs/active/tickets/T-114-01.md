## Context (self-contained)

Epic **E-29** / Story S-114. The church's first gate run (T-110) returned three judged views and one
**unparsed judge reply** at 225°, making the aggregate **REFUSAL (unparsed:-x-z)**
(`benchmarks/sculpture/multi-angle/church-challenge.json`). The no-re-roll rule correctly forbade an
inline retry — re-rolling *verdicts* is how gates get gamed — but a malformed reply **is not a
verdict**, and conflating the two lets one transport/format hiccup poison a milestone while creating
pressure to bend the rule ad hoc. Make the distinction structural. Sequenced after T-111-01 (it edits
the judge seam the closure milestone is using).

## Acceptance Criteria

- [ ] **Reply schema validation** at the judge seam (pure, unit-tested): a reply either parses to a
      verdict (then it is **final** — whatever it says, no re-ask ever) or is **malformed** (schema
      violation / unparseable), a distinct state.
- [ ] **Bounded re-ask on malformed only** (declared limit, e.g. 2; same prompt, same pinned model,
      no prompt mutation): tested with synthetic malformed replies (recovers on attempt 2; exhausts to
      REFUSAL). **Every reply committed** — malformed ones included — as the audit ledger
      (`replies[]` with parse status per attempt).
- [ ] **No re-roll possible by construction**: a unit test proves a parsed verdict short-circuits the
      re-ask path (the policy cannot be invoked on a parsed reply).
- [ ] **The church 225° regression**: that view re-judged under the policy behind the named `npm run`
      (the one open REFUSAL — re-judging an *unparsed* view is the policy's purpose, not a verdict
      re-roll); the resulting aggregate recorded. Existing parsed verdicts everywhere **untouched**.
- [ ] No threshold/azimuth/judge-contract change (I/O handling only — the prompt and judge model are
      byte-identical); instrument-diff on the re-judged record shows only the new `replies[]` ledger;
      `npm test` green.
