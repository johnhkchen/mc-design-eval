## Context (self-contained)

Epic **E-32** / Story S-128. The project owns a dozen-plus build techniques (gable/hip/pyramid roofs,
arches, timber-frame grammar, opening dressing, spray/paint ops, hollowing, floorplans) accreted as
epic-specific fixes with heterogeneous interfaces. The **brush** is the unit of capability:
parametrized, composable, unit-tested, **preview-carded**. The E-31 idiom registry (T-124-01) is the
seed; this ticket makes the contract universal — the registry becomes the single door to every build
technique, and the catalog makes capability visible and countable (the baseline the factory milestone
measures growth against).

## Acceptance Criteria

- [ ] **The brush contract** (schema + loader, pure, unit-tested): parameter schema, composition
      interface (what a brush consumes/emits so brushes chain — placements in/out over an occupancy +
      zone/feature context), test requirement, and the **preview-card** requirement (the brush
      rendered on a declared synthetic subject through the fixed lens).
- [ ] **Full inventory registered**: the T-124 idiom generators plus the E-23 spray/paint ops, opening
      dressing, hollow, floorplan — every technique reachable through the registry contract. New
      brushes can only enter through it (E-32 Rule 1).
- [ ] **Behavior-preserving migration**: existing committed records re-verify **byte-identical**
      through registration (`--offline`/`--repro` asserts — the T-113 discipline); the registry wraps,
      it does not fork.
- [ ] **The catalog**: one committed page rendering every brush with its preview card + parameter
      docs; the **brush count** recorded as the factory baseline.
- [ ] No per-building constants; `npm test` green.
