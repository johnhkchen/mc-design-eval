## Context (self-contained)

Epic **E-51** / Story **S-197**. The T-194/T-195 renders show the gatehouse is an **open colonnade**
(closureOf ~0.05): the carve (T-194) and relief (T-195) hands are correct but can't read because there's no
closed wall under them. Reviewer's ordering note (2026-06-17): **form before detail** — carving a doorway must
come after the overall form is ready, not all at once up front.

Two coupled deliverables:

1. **Close-the-shell form hand:** build a **dense, closed wall shell** from the recognition program's
   **masses[] / absolute footprint** (not the ragged GLB-voxelized occupancy) — [[wall-construct-needs-dense-shell]]
   (replace-via-occupancy walls only climb on dense shells; sparse → colonnade).
2. **Climb ordering:** detail tools (`carve_arch`, `relief_walls`, `band_eave`) **gated on form-readiness**
   (closureOf ≥ threshold), so the loop builds coarse form first and never carves/dresses an open frame.

## Falsifiable claim (anti-hedge — lead with how it fails)

The form hand closes the gatehouse shell (closureOf ~0.05 → toward watertight) and the ordering gate blocks
detail on an open form / allows it on a closed one. **Fails if:** the program footprint can't produce a dense
shell on this seed (deeper geometry wall → name it, [[cottage-gate-and-volume-gate-are-one-fix]]); closing the
shell regresses the already-won roof/form (not composable with prior climb state); or the gate threshold is
miscalibrated (blocks a legit detail or passes one on a still-open form).
