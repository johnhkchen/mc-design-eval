## Context (self-contained)

Epic **E-16** uses real TRELLIS GLBs (`benchmarks/sculpture/glb/{koi,heart}.glb` — gitignored local
artifacts; regen via `benchmarks/sculpture/trellis-glb.mjs` if missing) as a **3-D form target** for the
E-15 surgical loop. The loop hill-climbs a silhouette IoU; its old target was a **flat concept**, too
blunt for a local edit to move. A GLB fixes that once we can project it to a **target silhouette**.

A silhouette needs **no GL** — it's the filled outline of the mesh's triangles projected to 2-D. So build
a **pure software rasterizer**: parse the GLB geometry (vertices + triangle indices — see the glTF
JSON/binary parse in `trellis-glb.mjs` `inspectGlb`), transform by a camera matrix (reuse
`render/src/camera.mjs` `framedCamera` / `boxOf` / `boundingSphere` so it matches the build's render
camera), project, and fill each triangle into a **binary mask** — whole-object and masked to a region's
projected 3-D bbox.

## Acceptance Criteria

- [ ] A pure module (e.g. `src/form/glb-silhouette.mjs`): load a GLB's vertices + triangles, project from
      a view (matching `SCULPTURE_VIEW_3Q` from `src/sculpture.mjs`), rasterize a **binary silhouette
      mask** — whole-object and **per-region** (masked to a 3-D bbox's projected bounds). Deterministic,
      **GL-free**.
- [ ] Unit tests on a **synthetic mesh** (a unit cube): known silhouette area/shape from a known view;
      per-region mask restricts correctly; projection is stable/deterministic. Suite stays offline (no 5
      MB GLB in the unit tests).
- [ ] One **real** `koi.glb` silhouette rendered to a PNG and eyeballed (saved under the run/glb area) as
      a sanity check that the projection reads as a koi outline.
- [ ] `npm test` green.
