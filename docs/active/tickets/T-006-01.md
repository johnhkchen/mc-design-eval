## Context

Epic E-08 / story S-006 / spec §7, §9. First run-the-test in the overnight chain. **Champion = run 014**
(Taj `vRefRevise-designdoc`: craft/color split + facade-is-one-plane + no-flat-fields). The only quality
dimension still at *competent* is **`detail`** (journal P15) — large flat brick/niche/plinth fields
persist, and the `NO LARGE FLAT FIELDS` clause moved it less than the structural one-plane clause did.

**One hypothesis only.** Design and justify a single, more powerful detail lever, then test it. Candidate
directions (pick ONE in Design, grounded in the render of run 014 — `benchmarks/temple-facade/runs/
014-vRefRevise-designdoc/render.png`): a **dedicated detail-only pass** that edits *only* flat fields
through the existing revision seam (per P9, a fenced pass beats stacking detail into the monolithic
build); explicit **per-region articulation minimums** (each plane > ~6 wide must carry ≥1 named
relief device); or a **paneling/string-course grammar** the build must apply. This ticket has latitude to
make a substantive prompt change (E-08: powerful experimentation, accountable by recorded diff) — but
change ONE thing so the result is attributable.

Seams: build = `baml_src/facade.baml` (regenerate the client with `npm run baml:gen` after editing, it is
gitignored); revision = `composeRefRevisionPrompt` in `benchmarks/temple-facade/run.mjs`. Run with
`node benchmarks/temple-facade/run.mjs --approach vRefRevise-designdoc --ref references/taj_mahal.png`.
Do NOT edit the rubric (`baml_src/judge.baml`) or the brief (`benchmarks/temple-facade/task.mjs`).

## Acceptance Criteria

- [ ] Exactly ONE detail lever is chosen in Design with a written rationale and applied as a prompt diff
      (build and/or revision); `npm test` stays green and the client is regenerated if `facade.baml`
      changed.
- [ ] The Taj `vRefRevise-designdoc` trial runs end to end; **both** `round-0.png` (build) and
      `render.png` (post-revision) are scored with the categorical judge (median of 3), per P14.
- [ ] A new **attempt-log entry** is appended to `docs/knowledge/design-learnings.md` recording: the
      **prompt diff**, the **A/B per-dimension scores** (round-0 vs render), the judge's notes, and a
      **verdict** — promote / scope / discard.
- [ ] **Promotion rule:** keep the change as the new champion ONLY if `detail` rises a full category to
      *strong* with **no regression** on proportion/color/fidelity and overall stays ≥ *strong*; else
      revert the prompt change and record the negative result (it still counts — a falsified lever is a
      finding). A within-band wobble does not promote.
- [ ] **Control for detail noise (important):** `detail` is boundary-noisy — the champion scored `detail`
      *competent* in run 014 but *strong* in run 015 on the **identical** config. A single `detail=strong`
      is therefore NOT evidence of a real lever effect. Require robustness before promoting: `detail`
      *strong* across **2 generations** of the lever variant (or a clear, describable visual articulation
      increase vs the run-015 baseline render `runs/015-vRefRevise-designdoc/render.png`). Record both the
      lever runs and the baseline comparison in the journal entry.
- [ ] Renders + `summary.json` retained under `benchmarks/temple-facade/runs/<id>/`.
