## Context (self-contained)

Epic **E-16**, Arm B — the founding image→3D question: can voxelizing a 3-D **mesh** beat text→JSON
geometry (which keeps palette + parts but loses *form/line* — the koi S-curve flattens, the heart aortic
arch never loops)? We have real meshes (`benchmarks/sculpture/glb/{koi,heart}.glb`, ~95–106K tris;
gitignored, regen via `trellis-glb.mjs`). This ticket builds the geometry half: **mesh → occupancy voxel
grid** at a target scale. Pure geometry, no GL, no color yet — fully unit-testable on a synthetic mesh.

Size the grid so the mesh's longest edge is ~`scale` voxels (reuse the `vConcept` scale convention,
`src/sculpture.mjs` `DEFAULT_SCALE`/`SCALE_MIN`/`SCALE_MAX`, so a voxelized build is comparable to the
text→JSON build at the same scale). Decide occupied/empty by a deterministic test (point-in-mesh via
ray-cast parity / winding number, or triangle-vs-cell intersection for a watertight shell).

## Acceptance Criteria

- [ ] `voxelizeGlb(glb, { scale }) → occupancy` (occupied integer cells + bounds) — deterministic, **pure,
      GL-free**, sharing the GLB mesh parse with T-048-01 (no duplicate parser).
- [ ] Grid sized so the longest edge ≈ `scale` voxels, clamped to `SCALE_MIN/MAX`; same scale convention
      as `vConcept`.
- [ ] Unit tests on a **synthetic cube** mesh: known occupancy (a solid/shelled cube of the expected cell
      count) from a known scale; deterministic. Offline (no 5 MB GLB in unit tests).
- [ ] A real koi + heart occupancy **count sanity-checked** vs their scale (recorded, not asserted) so the
      voxelization is plausibly dense/hollow as expected.
- [ ] `npm test` green.
