## Context (self-contained)

Epic **E-32** / Story S-131. The model is good at decomposition; AI coding (lisa) is good at
implementing well-specified reusable components; the missing piece is the conveyor: a **design
backlog** of brush work-items generated from a style concept. The runaway risk is handled
structurally (E-32 Rule 3, the T-119-style twin): drafts land **outside lisa's scan dirs**; human
promotion is the only path to scheduling — the system never schedules its own work.

## Acceptance Criteria

- [ ] **The factory runner** (the T-129 decomposition function + composition logic): formed style
      (T-130) + current registry state (T-128) in → **brush work-item drafts** out, written to
      `docs/active/backlog/` — verified **outside** `.lisa.toml`'s scan dirs (a test asserts the
      config; lisa never sees a draft).
- [ ] **Draft quality contract**: each draft is self-contained in house ticket style — brush name +
      purpose, parameter schema sketch, composition notes (what it chains with), test plan, preview
      subject, Context/AC skeleton. The measure: a promoted draft runs through lisa **without
      rework** (rework, if any, recorded — it is the factory's quality metric).
- [ ] **Duplicate detection**: a requested brush that the registry already owns (or that an owned
      brush covers via parameters) is caught and emitted as a *parametrization note*, not a new
      work-item — unit-tested both ways.
- [ ] **The promotion flow documented** (one page, linked from the backlog dir): backlog → human
      review → move to `docs/active/tickets/` with story assignment — planner/human only, never
      automated.
- [ ] **Live proof against the milestone style**: drafts generated for the T-130 new style's
      brush-needs; **≥1 draft promoted by hand and executed by lisa cleanly**; the rework measure
      recorded. Raw replies committed; `npm test` green.
