## Context (self-contained)

Epic **E-26** / Story S-099. The witnessed case from the audit: the cottage concept's windows have
**trapdoor shutters** and **fence infill**; the build's windows are bare holes. Openings are first-class
in the structural read (`src/view/structural-read.mjs` `openings`); the fixture path is proven by
T-097-01; the kit (T-096-01) declares each opening's treatment. This ticket is the op that walks the
openings and applies it.

## Acceptance Criteria

- [ ] A **deterministic opening-dressing op** (pure core, unit-tested on synthetic openings): per opening
      instance, apply the kit's treatment — **fence infill** in the aperture, **trapdoor shutters**
      flanking (correct facing/orientation states), **lintel/sill** from the frame block — sized to the
      opening's actual dimensions.
- [ ] **Conflict honesty** (E-26 honesty rule): when an opening is too small for its full treatment
      (e.g. a 1-block aperture can't hold fence + shutters + lintel), the op records the conflict and the
      chosen reduction by name — never silently drops or silently crams.
- [ ] **Integrity-compatible**: dressed openings remain *openings* to the E-25 shell-integrity stage
      (S-091 allow-list) and pass closure as dressed (T-097-01 semantics) — unit-tested integration case.
- [ ] **Cottage run** behind the named `npm run`: **every window** dressed with shutters + fence infill,
      the door framed, orientations correct; before/after renders at gate angles where windows are
      visible. The render is the evidence (E-25 Rule 1).
- [ ] No subject-specific constants; no hand-edits; `npm test` green.
