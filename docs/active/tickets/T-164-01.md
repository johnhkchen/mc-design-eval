## Context (self-contained)

Epic **E-39** / Story **S-164**. Layer A — the structured "what's wrong" judge. A BAML function
`DiagnoseBuild(concept, render[, style]) → Critique` (T-163-01 schema) that fills `expected/present/missing`
per `department`. Single-style (rustic) here; the per-style `expected` is T-165. This replaces the
*critique half* of the fused `CritiqueWorkshopRound`/`WorkshopReply`.

## Falsifiable claim (anti-hedge — lead with how it fails)

A judge that emits per-department expected/present/missing gives the builder a more actionable target than
the old freeform `issue` prose, without losing diagnostic nuance. **Fails if:** the structured form drops
nuance the prose carried (report which), or the model fills the fields with vacuous text (then structure
without grounding — the prompt needs the concept/program grounding the fused call had).

## Acceptance Criteria

- [ ] `DiagnoseBuild` BAML fn → `Critique`; rustic prompt grounded on the concept + program; every item
      carries a valid `Department` (T-163-01 enum).
- [ ] `b.parse` fixture test against a captured golden; a smoke run on one real (concept, render) pair shows
      non-vacuous expected/present/missing.
- [ ] Pure `.mjs` render-args serializer (mirrors the existing `critiqueRenderArgs` pattern) so the prompt
      bytes are testable.
- [ ] `npm test` green; no gate vocabulary (this is creation-loop, not the frozen judge).
