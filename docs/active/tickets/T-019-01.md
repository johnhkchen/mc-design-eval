## Context

Epic E-10 / story S-019. Build the block→Lab color table from `minecraft-assets` (1.20.1). For each
**full-cube, survival-obtainable** block, compute a representative color (mean of opaque texture pixels;
use the **side** face for directional blocks; first frame for animated) and convert to CIE L\*a\*b\*. Cache
the result as data the color engine (S-020) consumes. Follow `docs/knowledge/cielab-block-matching.md`.

Gotchas (from the research doc): `minecraft-assets` is **not installed** and has a known **CJS-`require`**
issue — add it and import as ESM or read `data/1.20.1/` PNGs directly. **Exclude** biome-tinted blocks
(grass/leaves/water/vines) — or pin a fixed tint — since their textures are greyscale; **exclude**
non-full-cube blocks (stairs/slabs/fences/panes/torches); average **opaque pixels only** for blocks with
alpha. The PNG decode can use a small dependency or a minimal decoder.

## Acceptance Criteria

- [ ] `minecraft-assets` added as a dependency and loadable (ESM/data-path; the CJS gotcha worked around).
- [ ] A builder produces a cached **block→Lab table** for full-cube survival 1.20.1 blocks: each entry
      `{ block, rgb, lab }`. Biome-tinted + non-full-cube blocks are excluded (documented which).
- [ ] **Unit tests** assert sanity on known blocks: e.g. `gold_block` lands warm/yellow (high b\*, mid
      L\*), `coal_block`/`blackstone` near-black (low L\*), `quartz_block` near-white (high L\*),
      `lapis_block` blue (negative b\*). Tests derive expectations independently of the builder.
- [ ] The table is regenerable by a documented command; large texture assets stay gitignored if bulky.
- [ ] `npm test` green.
