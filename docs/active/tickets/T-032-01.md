## Context

Epic E-12 / story S-032. Extend the render harness with an **orbit/turntable mode**: given a build
artifact (its in-memory voxel world), render N frames sweeping the camera **azimuth** 0→360° (fixed
elevation/distance), through `prismarine-viewer` + real `minecraft-assets` textures — producing a rotation
frame sequence (and optionally an encoded clip if `ffmpeg`/gif tooling is available). Reuse the existing
head-on render path; the only new parameter is the azimuth sweep.

Independent of the content desks — it's a rig capability. Keep it general (any artifact in), so E-11's
review bookend can call it for multi-view inspection.

## Acceptance Criteria

- [ ] An orbit render function/CLI takes an artifact + frame count and writes a sequence of N renders at
      evenly-spaced azimuths (gitignored output, like other renders).
- [ ] Run it on at least one real build (a `runs/<id>` artifact) and produce a rotation sequence; spot-check
      that frames show the structure from different angles (not all identical).
- [ ] The capability is artifact-general (no facade/temple specifics), so it is reusable by E-11.
- [ ] A test covers the azimuth math (N frames → correct evenly-spaced angles) without requiring a full
      headless render in CI; `npm test` green.
