## Context

Epic E-14 / story S-041 — the **build end**. Wire E-10 into the **live build** so placement hits the
concept's **value**, not just its name. This is the direct cure for the moai drift (faithful form,
`gray_concrete` too dark). Division of labor: the **model owns form + where** (region → intent); the
**engine owns which block** hits that region's value.

Do: in the build path (`benchmarks/sculpture/run.mjs` + `src/sculpture.mjs`
`composeSculptureBuildPrompt`), after the model proposes the artifact, **extract the concept's realized
palette** (`gridFromImage` / `extractPaletteFromImage`) and **snap placements to value-true blocks** via
`nearestLab` against the T-039-01 contract — replacing name-by-hue choice. Keep it additive (a `.v2`
build path; `.v1` intact). A/B the **moai** (the documented value case) + the **sword** and
**pineapple** vs their E-13 renders; surface the value-true blocks the engine chose vs the model's
original names.

## Acceptance Criteria

- [ ] The build snaps block choice to **value-true blocks** via E-10 `nearestLab` against the S-039
      contract (the concept's realized palette extracted with `gridFromImage`/`extractPaletteFromImage`),
      additive to the untouched `.v1` build path.
- [ ] An **A/B** is recorded for ≥3 subjects (moai + sword + pineapple): E-13 `.v1` render vs the
      value-matched render, plus the per-region block swap (original name → value-true block).
- [ ] The **moai value-drift** is explicitly addressed — `gray_concrete` → a value-true block — or, if
      it regresses elsewhere, that's shown honestly.
- [ ] Renders saved; `npm test` green (pure block-choice logic unit-tested; the live run is GL/metered).
