## Context (self-contained)

Epic **E-54** / Story **S-210**. The ergonomic fix the arch work exposed. The aperture hand widens the gate
**wherever the build already has a slot** — `carveTargetCells` (`src/view/aperture-carve.mjs:61`): *"the EXISTING
aperture (the build positions the slot); width from the program."* So a **centered** gate depends on where a
pre-existing (often GLB-inherited) void sat, not on intent. Make centering a first-class, by-construction
operation.

Add a **`centerOnFace`** helper (pure): given a declared wall face (the footprint edge for the opening's `dir`)
and an opening width `w`, compute the centered column span (`uLo = floor((faceW − w)/2)`, `uHi = uLo + w − 1`),
independent of any existing slot; feed it to `rebuild_arch` (T-203) / `carve_arch`. The front face derives from
the **recognition-declared gate/front** (not a stray void; the E-50 orientation finding). A centered wide arch
reads as a proper gatehouse gate.

## Falsifiable claim (anti-hedge — lead with how it fails)

A declared gate places **centered on its wall face by construction**, reads centered from the front azimuth, and
passes the aperture-coherence gate. **Fails if:** a GLB-inherited slot remains **beside** the new centered
opening → a double opening / ragged edge (then centering needs the inherited slot removed/rebuilt first, not
overlaid — handle or name it); the face is **ambiguous** on a near-square footprint (tie the front to the
recognition-declared gate, don't guess); or centering moves the opening off a support the lintel needs (check at
scale).
