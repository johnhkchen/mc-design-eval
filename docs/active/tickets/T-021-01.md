## Context

Epic E-10 / story S-021. The headline deliverable. Given a facade concept image (e.g.
`benchmarks/temple-facade/concepts/taj-C-flash.png`), produce the **canonical block palette** it uses.

Pipeline: decode the image → optionally ignore the pure-black background → **cluster** the foreground
colors (median-cut or k-means **in Lab space**, K≈6–12) → for each cluster centroid, `nearest()` to the
**block→Lab table** (S-019) via the engine (S-020) → **merge** centroids that map to the same block,
summing coverage → sort by coverage → emit `{ block, repColor (hex+lab), coveragePct }[]` and a one-line
human-readable description. Support two modes: match against the **full survival full-cube set**
(discover the palette) or against a **provided whitelist** (validate the design doc's declared manifest).

## Acceptance Criteria

- [ ] A function/CLI takes an image (+ optional palette whitelist, K, background-color to drop) and
      returns the **canonical palette**: ordered `{block, repColor, coveragePct}` + a human-readable
      description string.
- [ ] Clustering is done **in Lab**, matching uses the S-020 engine + S-019 table; centroids that map to
      the same block are merged with summed coverage; the background is excluded.
- [ ] **Tests** on a synthetic image with known color regions (e.g. a few flat color blocks in known
      proportions): the extracted palette names the expected blocks with coverage within tolerance, and
      ordering is by coverage. Expectations derived independently of the extractor.
- [ ] Run it on at least one real `concepts/` image and record the resulting palette + description in the
      journal (`design-learnings.md`) — a worked example of "blocks in this facade".
- [ ] `npm test` green.
