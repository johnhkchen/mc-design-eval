## Context (self-contained)

Epic **E-37** / Story S-154. Four "build a subject" chains exist; generate-first and pattern-book each
have their own Stage-4 realizer, and the workshop is bolted onto pattern-book's *rougher* seed. T-150-01
proved the cost — the gable fix went into generate-first while the *measured* barn is the workshop one.
Unify: **generate-first's parametric realizer becomes the Stage-4 seed the workshop iterates.** Depends
on **E-36** (de-freeze) — the same runners; merge on de-frozen ground (`builds/` free, `measurements/`
allowlisted). The philosophy's stage assignment is the architecture of record — realize it, don't
re-derive it.

## Acceptance Criteria

- [ ] **Generate-first is the workshop's Stage-4 seed.** The workshop loop seeds from generate-first's
      parametric build (`provision-generate` realizer: GLB-fit + kit, gable-as-wall, overhang,
      articulation) **instead of** pattern-book's seed brushes. One realizer feeds the one loop — a
      construction fix now lands in the chain that gets measured. The pattern-book seed-brush stage is
      retired from the live path (archived in S-156).
- [ ] **One entry point.** `npm run build:<subject>` runs recognize (Stage 3) → generate-seed (Stage 4)
      → workshop (Stage 5) → final, for the registered subjects. The **gate is a separate explicit
      step** (frozen, billed) — `build` never spawns it.
- [ ] **Behavior parity or recorded improvement.** The unified chain produces a build at least as good
      as the prior workshop path (rendered beside concept, E-36); any difference is *named* (the
      generate-first seed is cleaner — expected). No judge run in this ticket.
- [ ] **First `STRUCTURE.md`.** A one-screen canonical map: Stage → owning module → artifact → entry
      point → (archived). Authoritative; S-157 makes it enforced.
- [ ] Replay/offline byte-identical on the unified chain's deterministic stages; `npm test` green; no
      per-building constants; subscription shim only.
