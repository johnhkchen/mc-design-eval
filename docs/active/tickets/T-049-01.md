## Context (self-contained)

Epic **E-16**, Arm A — the direct test of E-15's cliffhanger. E-15's surgical loop (`reviseLoop` in
`src/form/`) rolled back **2 of 2** form edits on the text→JSON koi/heart builds because its target was a
**flat concept silhouette** (whole-object IoU: koi 0.481, heart 0.347 — `benchmarks/sculpture/
form-baseline.json`). It left a **`glbFormTarget` seam** (`src/form/form-target.mjs`, currently throws)
for a real 3-D target. The GLBs exist (`benchmarks/sculpture/glb/{koi,heart}.glb`) and T-048-01 projects
them to a target silhouette. The seam's whole design is that swapping concept→GLB touches **nothing** in
observe/diagnose/accept — the loop consults only `scoreRender(renderPath, R)`.

## Acceptance Criteria

- [ ] `glbFormTarget({ glbPath, view })` implemented behind the existing `scoreRender(renderPath, R)`
      interface (replacing the throwing stub): score the build render's silhouette against the GLB's
      projected silhouette (T-048-01) — **whole-object IoU** and a **true per-region IoU** masked to R's
      projected bounds (the signal the flat concept could not give).
- [ ] The E-15 `reviseLoop` re-run on the **text→JSON** koi + heart builds with `formTarget:
      glbFormTarget(...)` (via `liveFormScore`/`resolveFormTarget`); **before/after form IoU + judge** vs
      the E-13 baseline recorded (`benchmarks/sculpture/glb-formtarget-ab.{md,json}`).
- [ ] Demonstrated: **no change to the loop control flow** was needed (the seam invariant — `glbFormTarget`
      is a drop-in `scoreRender` object).
- [ ] Honest: state whether the 3-D target moved the loop on these builds (a null result is a real
      finding). Pure scoring logic unit-tested; live render/model is GL/metered. `npm test` green.
